# 수계(펌프) 유량센서 추가에 따른 변경사항 정리

**작성일**: 2026-08-14
**대상**: 소프트웨어/서버 담당자 공유용
**배경**: 기존 수계 노드는 압력(INA219 전류 + 압력센서)만 측정하는 구조였으나,
유량센서(YF-S201, 홀센서 펄스 방식)를 배관에 직렬로 추가하기로 결정.
호스니플 부속 도착(8/19) 시점에 최종 결합 예정.

---

## 1. 하드웨어 변경사항

| 항목 | 기존 | 변경 후 |
|---|---|---|
| 배관 구성 | 펌프 → 압력센서 티(곁가지) → 니들밸브 | 펌프 → **유량센서(직렬)** → 압력센서 티(곁가지, 기존과 동일) → 니들밸브 |
| 압력센서 결합 방식 | 티에 곁가지로 얹힘 | **변경 없음** (그대로 유지) |
| 신규 부품 | - | YF-S201 유량센서 1개, 신주 호스니플(1/2-8mm) 2개 |
| ESP32 GPIO 핀 | INA219(I2C), 압력센서(ADC 등) | 위 두 개 + **유량센서 펄스 입력용 디지털 GPIO 1개 추가** (인터럽트 가능한 핀 권장) |
| 유량센서 방향 | - | 센서 몸통에 흐름방향 화살표 있음 → **역방향 장착 금지** (조립 시 반드시 확인) |

> 압력센서 결선/코드는 그대로 두면 됨. 유량센서는 완전히 별개 라인으로 병렬 추가.

## 2. ESP32 펌웨어 변경사항 (하드웨어 담당 → 작업 예정)

### 추가해야 할 것
- 유량센서 펄스 카운트용 인터럽트 핸들러

```cpp
volatile int pulseCount = 0;

void IRAM_ATTR flowISR() {
  pulseCount++;
}

void setup() {
  pinMode(FLOW_SENSOR_PIN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(FLOW_SENSOR_PIN), flowISR, FALLING);
}

// 1초 주기로 호출
float getFlowRate() {
  float flowRate = pulseCount / K_FACTOR; // K_FACTOR는 실측 캘리브레이션으로 결정 (L/min)
  pulseCount = 0;
  return flowRate;
}
```

- `K_FACTOR`(펄스→유량 환산계수)는 데이터시트 참고값이 있지만, **실측 캘리브레이션 권장**
  (일정 시간 펄스 수 vs 체적법 실측 유량 비교해서 보정)

### 바뀌지 않는 것
- INA219 전류 읽기 로직
- 압력센서 읽기 로직
- ESP-NOW / WiFi 통신 구조 자체

## 3. 전송 데이터 포맷 변경 (소프트웨어/서버 담당자 확인 필요)

### 기존 JSON 구조 (예시)
```json
{
  "node": "sugye",
  "timestamp": "...",
  "current": 0.85,
  "pressure": 3.2
}
```

### 변경 후 JSON 구조
```json
{
  "node": "sugye",
  "timestamp": "...",
  "current": 0.85,
  "pressure": 3.2,
  "flow_rate": 12.4
}
```

- **필드 1개(`flow_rate`) 추가**, 나머지는 동일
- 서버 측 DB 스키마 / 테이블에 `flow_rate` 컬럼(FLOAT) 추가 필요
- 기존에 쌓인 데이터(유량센서 이전 데이터)는 `flow_rate = null` 또는 수동 체적법으로 근사 기록한 값으로 소급 채움 예정

## 4. 대시보드(Flutter 앱) 변경사항

| 항목 | 내용 |
|---|---|
| 실시간 표시 | 수계 노드 화면에 **유량(L/min) 표시 위젯 추가** (전류/압력 표시하던 자리 옆에) |
| 그래프 | 기존 전류/압력 시계열 그래프에 **유량 축 추가** (또는 별도 서브 그래프) |
| PDF 리포트 | 점검 결과 PDF에 유량 값도 포함되도록 템플릿 필드 추가 |
| 이상 판정 로직 | (선택) 유량이 비정상적으로 낮으면 "배관 폐색 의심" 같은 표시 추가 가능 — 우선순위 낮음, 시간 되면 |

## 5. ML 학습 스크립트 (`train_pump_classifier.py`) 변경사항

- **입력 피처(feature) 1개 추가**: 기존 (전류파형 특징값 + 압력) → (전류파형 특징값 + 압력 + **유량**)
- 학습 데이터 CSV/데이터셋 컬럼에 `flow_rate` 추가
- 정상/비정상 라벨링 시, 이제 유량 조건까지 포함해서 "정상 범위" 정의 가능
  (예: 특정 전류파형이어도 유량이 비정상적으로 낮으면 이상으로 재분류 가능)
- **아직 수계 데이터축적 자체가 시작 전이므로**, 스크립트를 "뜯어고치는" 게 아니라
  **처음부터 유량 피처 포함해서 설계**하면 됨 → 오히려 지금 시점에 확정하는 게 깔끔함

## 6. 일정상 참고사항

- 유량센서: 8/15(내일) 도착 예정
- 호스니플(배관 연결 부속): 8/19 도착 예정 → **실제 배관 결합은 8/19부터 가능**
- 그 전까지는 유량센서 없이 **전류파형 + 압력 + 수동 체적법(비커+스톱워치) 근사 유량**으로
  데이터축적 파이프라인(펌웨어→서버 저장) 자체를 미리 검증해둘 예정
- 8/19 이후 유량센서 결합 시, 서버/DB/대시보드 쪽 `flow_rate` 필드가 미리 준비되어 있어야
  바로 정밀 데이터 축적으로 전환 가능 → **소프트웨어 담당자는 이 문서의 3~4번 항목을
  8/19 이전에 미리 반영해두는 것을 권장**

## 요약 (한 줄 정리)

> 압력센서 로직은 그대로 두고, 배관에 유량센서 하나를 직렬로 추가한다.
> ESP32는 펄스카운트 함수 하나, 전송 JSON은 필드 하나(`flow_rate`), DB는 컬럼 하나,
> 앱은 표시 위젯 하나, 학습 스크립트는 피처 하나 — **딱 수계 파이프라인에만 국한된 확장**이며
> 다른 4개 노드(자탐1/2, 가스계, 소화기, 유도등)는 전혀 영향받지 않음.
