# 자탐1(차동식구역) 실물 실험 — 오늘의 기록

> 루프저항 열화 회로 + 온도센서를 처음으로 브레드보드에 조립하고 작동 확인한 세션입니다.

> **📌 업데이트 — 센서 교체됨**: 최초 조립 시에는 자재 박스에서 발견한 범용 NTC 온도센서 모듈로 진행했으나, 이후 정식 설계 부품인 **TS0202로 교체**했습니다. 아래 "최초 조립" 내용은 이력으로 남기고, 교체 이후 내용은 문서 하단 [TS0202 교체 이후](#ts0202-교체-이후) 섹션에 별도 정리했습니다.

---

## 오늘 한 것 (최초 조립, NTC 모듈 기준)

- 루프저항 열화 감지 회로(고정저항+가변저항+션트저항) 조립
- NTC 온도센서 모듈 조립
- ESP32 DevKitC에 `fire_alarm_differential_node.ino` 업로드
- 시리얼 모니터로 값 확인 및 문제 진단

## 최종 배선 내역 (최초 조립, NTC 모듈 기준)

### 루프저항 열화 회로
```
ESP32 5V ──[220Ω 고정저항]──[가변저항(0~1kΩ)]──[100Ω 고정저항]── GND
                                    │(wiper)              │
                              (한쪽 끝 핀 사용)      ADS1115 A1로 분기
```
- 가변저항: 3핀 중 **wiper(가운데)와 한쪽 끝 핀만 사용**, 나머지 한 핀은 미사용
- ADS1115 A1 연결 지점: **가변저항과 100Ω 사이** (100Ω 양 끝 중 GND 반대쪽)
- 200Ω 대신 **220Ω으로 대체** — 계산에 미치는 영향 미미해 그대로 사용

### 온도센서 (NTC 모듈, Keyes 계열)
```
센서 "-" → ESP32 GND
센서 가운데(라벨 없음, VCC) → ESP32 3.3V
센서 "S" → ADS1115 A0
```
- 이 모듈은 핀 라벨이 "S"와 "-"만 인쇄되어 있고, **가운데(라벨 없음)가 VCC**인 것이 표준 배치

### ADS1115
```
SDA → ESP32 GPIO21
SCL → ESP32 GPIO22
```

## 발견한 점 (트러블슈팅 기록)

### ① 라이브러리 미설치로 컴파일 실패
`ArduinoJson.h`, `Adafruit_ADS1X15.h` 둘 다 아두이노 IDE 라이브러리 매니저에서 별도 설치 필요했음. (다음 노드 작업 시에도 동일하게 필요)

### ② 업로드 시 포트 연결 실패 (Write timeout)
컴파일은 성공했지만 보드 업로드 단계에서 시리얼 타임아웃 발생 → 원인 특정은 못 했으나 재시도로 해결됨 (케이블 재연결 또는 BOOT 버튼 개입 추정)

### ③ 코드 상수가 실제 회로값과 다르게 설정되어 있었음
```cpp
// 수정 전 (placeholder)
const float SUPPLY_VOLTAGE = 24.0;
const float SHUNT_OHM = 10.0;

// 수정 후 (실제 회로값)
const float SUPPLY_VOLTAGE = 5.0;
const float SHUNT_OHM = 100.0;
```
코드 자체에 "실측 후 재조정" 주석이 있었던 부분 — 예상대로 수정 필요했음.

### ④ 온도센서가 NTC(부온도계수) 타입 — 코드 공식 방향이 반대였음
**증상**: 라이터를 대도 온도값이 거의 안 움직임
**원인 진단**: 멀티미터로 직접 측정한 결과, 라이터를 댈수록 **전압이 오히려 낮아짐**(1.3V→1.2V)을 확인. 원래 코드는 "전압이 오르면 온도도 오른다"는 전제로 짜여 있었는데, 실제 센서는 반대 특성(NTC)이었음.

**해결**:
```cpp
// 수정 전
float ratio = (v - TEMP_V_MIN) / (TEMP_V_MAX - TEMP_V_MIN);

// 수정 후 — 방향 반전
float ratio = (TEMP_V_MAX - v) / (TEMP_V_MAX - TEMP_V_MIN);
```
방향 반전 후 라이터 반응 확인됨 (전압↓ = 온도값↑로 정상 작동).

### ⑤ 절대 온도값은 아직 부정확함 (다음 단계 과제)
방향은 맞지만, `TEMP_V_MIN=0.5V, TEMP_V_MAX=4.5V`라는 기준값이 실제 센서 특성과 안 맞아 계산된 온도가 비현실적(-16~-18도)으로 나옴. 실측 전압 범위가 예상(0.5~4.5V)보다 훨씬 좁은 **0.45~1.45V** 안에서만 움직이는 걸로 확인됨 — 기존 상수를 그대로 못 쓰고 새로 캘리브레이션 필요.

## TS0202 교체 이후

### 교체 이유
자재 박스에서 정식 설계 부품인 TS0202(4핀: VCC/GND/AO/DO)를 발견해, 최초 조립에 쓴 범용 NTC 모듈에서 교체함. NTC 모듈로 이미 방향·회로 검증이 끝난 상태라, 교체 자체는 리스크가 낮다고 판단해 진행.

### 배선 (TS0202, 핀 라벨 인쇄됨)
```
빨강(VCC) → ESP32 3.3V
검정(GND) → ESP32 GND
흰색(AO)  → ADS1115 A0
갈색(DO)  → 미사용
```

### 교체 직후 트러블슈팅 — "루프 개방(단선) 의심" 재발
**증상**: 온도센서 교체 작업 도중 루프저항 회로(A1)에서 갑자기 단선 의심 에러 발생.
**원인**: 온도센서 배선을 만지는 과정에서 브레드보드의 루프저항 회로(220Ω/가변저항/100Ω) 쪽 접점이 물리적으로 헐거워진 것으로 추정. 코드는 그대로였고 A0(온도)와 A1(루프저항)이 서로 다른 채널이라 코드상 연관은 없음.
**해결**: 배선 재점검·재접속으로 해결.

### 재검증 결과
```
전압: 1.28V → 1.35V (라이터 켰다 껐다 하며 변화)
루프저항: 793Ω 안정적으로 재확인
```
- **방향성**: NTC 모듈 때와 동일한 패턴(전압↓=온도↑) 확인됨 — TS0202도 NTC 계열로 판단
- **루프저항 회로**: 재확인 완료, 정상

### 여전히 미해결 — 절대 온도값 캘리브레이션
NTC 모듈 때와 동일하게, `TEMP_V_MIN/MAX` 기준값이 실제 특성과 안 맞아 절대 온도값이 비현실적(-20도 근처)으로 계산됨. **방향·변화 감지는 유효**하나 절대값은 여전히 미확정 — 데이터 수집 단계에서 온도계로 정식 캘리브레이션 예정.

---



1. **온도센서 정밀 캘리브레이션**
   - 정확한 온도계(또는 온습도계) 하나 준비
   - 상온에서 전압-온도 기준점 하나 잡기 (예: "23도일 때 1.45V")
   - 열풍기로 가열하며 전압-온도 관계를 몇 개 더 찍어서 선형(또는 그에 가까운) 근사식 도출
   - 코드에 `REF_VOLTAGE`, `REF_TEMP_C`, `TEMP_SLOPE` 형태로 반영 (또는 `TEMP_V_MIN/MAX` 재설정)

2. **WiFi/서버 실연동**
   - `WIFI_SSID`, `WIFI_PASS`를 실제 값으로 교체
   - `SERVER_IP`를 라즈베리파이 실제 IP로 교체
   - 라즈베리파이 쪽 `main.py`가 이 패킷을 정상 수신하는지 확인

3. **자탐2(광전식구역)도 동일한 순서로 진행**
   - MQ-2, DHT22 배선 후 같은 방식으로 검증
   - 루프저항 회로는 자탐1과 동일 설계 재사용 가능

4. **디버그 출력 정리**
   - 오늘 임시로 추가한 `Serial.print("[디버그]...")` 줄들은 정식 검증 끝나면 제거하거나 주석 처리 고려
