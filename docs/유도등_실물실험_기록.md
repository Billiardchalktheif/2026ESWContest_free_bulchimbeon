# 유도등 실물 실험 — 방전시험 및 배터리 열화감지 기록

> 배터리 tap 회로를 처음 조립하고, DC 파워서플라이 시도 실패부터 AC 정품 결선 전환, 그리고 충전시간별 방전시험(1/2/4/6/8시간) 5회를 거쳐 판정 임계전압을 확정하기까지의 세션입니다.

---

## 오늘 한 것

- 유도등 내부 배터리 실측 (라벨 확인, 초기 방전상태 확인)
- 배터리 전압 tap 회로 조립 (분압 → 무납땜 직결 방식으로 변경)
- DC 파워서플라이 점등 시도 → 실패 → AC 정품 플러그 결선으로 전환
- 방전시험용 임시 코드 작성 (WiFi 없이 전압 로깅 전용, 시리얼 커맨드 트리거)
- 충전시간별(1/2/4/6/8시간) 방전시험 5회 진행, 판정 임계전압 확정

## 최종 배선 내역

### 배터리 전압 감지 회로

기존 설계(3셀 직렬 3.6V 가정, 저항분압 R1=R2=10kΩ)는 실측 후 폐기. 실제 배터리는 아래와 같이 확인됨.

```
배터리 라벨: WB-NC0601, Ni-Cd Battery, NS-AA600mAh 1.2V/1C(H)
→ AA 사이즈 단일셀 1개 (3셀 직렬 아님)
→ 완충전압 약 1.2~1.3V, ESP32 ADC 허용범위(0~3.3V) 안에 이미 들어옴
→ 분압 불필요, 보호저항 1개(1kΩ)만 직렬로 넣고 직결
```

```
배터리(+) 클립 ──[1kΩ 보호저항]──── ESP32 GPIO34
배터리(−) 클립 ──────────────────── ESP32 GND
```

**tap 방식**: 셀 직접납땜 → 리스크 판단으로 포기 → 클립 납땜(리지드 클립이라 삽입 경로 훼손 우려) → **최종적으로 무납땜 방식** 채택. 배터리와 클립 사이에 가는 점퍼선(피복 벗긴 심선)을 끼워 넣고 배터리 삽입 압력만으로 고정. 실측상 접촉 안정적으로 확인됨(시리얼 로그가 노이즈 없이 매끄럽게 우상향하는 것으로 검증).

### AC 전원 결선

```
백선 → 조립식 플러그 핀1 (나사 고정)
흑선 + 적선(함께 묶음) → 조립식 플러그 핀2 (나사 고정)
```

- 결선 전 통전 없이 저항 측정 → 1.8~1.9kΩ (유도등 백-흑선 자체 저항과 일치) 확인 후 통전
- 적선을 흑선과 같은 노드로 묶은 이유: 이 유도등은 3선식(수신기 연동, 평소 꺼짐) 하드웨어였음. 저희 목표(배터리 상시감시)엔 상시점등이 필요해, 적선을 흑선에 묶어 2선식(상시점등)처럼 강제 동작시킴
- 누전차단기 멀티탭 경유, 최초 통전 시 5~10분 발열/이상징후 관찰 후 방치

## 발견한 점 (트러블슈팅 기록)

### ① 배터리가 3셀 직렬이 아니라 단일셀이었음

겉모양이 원통형 건전지처럼 생겨 3셀 직렬 팩으로 가정했으나, 라벨 확인 결과 AA 사이즈 Ni-Cd 단일셀(1.2V)로 확인됨. 저항분압 설계(R1=R2=10kΩ) 전체를 폐기하고 직결(+보호저항 1개)로 재설계.

### ② DC 파워서플라이로 점등 시도 실패 — 원인은 캐패시터 강압 회로

**증상**: PWS-3005U로 0V부터 20V까지 서서히 올려도 전류가 계속 0mA. 극성을 반대로 해봐도 동일.

**진단 과정**:
1. 악어클립 접촉불량 의심 → 케이블/클립 각 구간 저항 측정으로 배제 (전부 정상)
2. 유도등 자체 단선 의심 → 백-흑선 저항 측정, 1.8kΩ으로 정상 확인
3. 최종적으로 유도등 내부가 **캐패시터 강압(용량성 드롭퍼) 회로**로 추정됨 — 캐패시터는 DC 정상상태에서 전류를 사실상 차단하므로, 극성·전압을 아무리 바꿔도 DC로는 원리적으로 점등 불가능

**해결**: DC 시도 자체를 포기하고 AC220V 정품 플러그 결선으로 전환.

### ② 육안 관찰 결과가 DC 시도의 오류를 뒷받침함

이후 실험 과정에서 이 유도등이 실제로 **정전 감지 시 배터리로 자동전환**되는 정상 소방 유도등 동작을 보인다는 게 확인됨 (AC 플러그를 뽑는 즉시 EXIT 표시부 9개 LED가 전부 점등). DC로 안 켜졌던 건 유도등 결함이 아니라 시험 방법 자체가 이 회로 특성과 안 맞았던 것으로 결론.

### ③ 배터리 초기 상태가 심방전 — 접촉불량과의 구분이 필요했음

**증상**: 무납땜 tap 연결 후 ESP32가 계속 raw=0을 출력.

**진단 과정**: 배터리를 단독으로 떼어내 멀티미터로 직접 측정해도 30~56mV로 동일하게 낮게 나옴 → 접촉불량이 아니라 배터리 자체가 심방전 상태임을 확인. 추가로 ESP32 ADC가 기본 감쇠(11dB, 0~3.3V 풀스케일) 기준 100mV 이하 구간에서 raw=0으로 읽는 특성이 있음을 확인, `analogSetPinAttenuation(pin, ADC_0db)`로 감쇠를 낮춰 저전압 구간 분해능 개선.

### ④ 물리 방전시험 버튼 신뢰성 문제 → 시리얼 커맨드로 우회

원래 설계는 GPIO13 물리버튼(`INPUT_PULLUP`+`FALLING` 인터럽트)으로 방전시험을 트리거하는 구조였으나, 다른 프로젝트에서 동일 방식 버튼이 "계속 눌린 것으로 인식"되는 문제를 겪어 신뢰성 확보 전까지 보류. 대신 시리얼모니터에 `s` 입력 시 스톱워치를 시작하는 방식으로 임시 대체(`evac_light_discharge_test.ino`). 실제 배포 시에는 물리버튼 문제 해결 또는 "전압 급락 자동 감지" 방식으로 트리거 전환 검토 필요.

## 방전시험 프로토콜

### 실험 방법

1. 유도등을 AC220V 정상 결선 상태로 충전 (지정 시간만큼)
2. 충전 시간 경과 후 전원 플러그를 뽑는 순간 시리얼모니터에 `s` 입력 → 스톱워치 0초 시작
3. 이후 1초 간격으로 배터리 전압을 자동 로깅
4. 육안으로 EXIT 표시부 밝기 변화를 관찰하며 아래 3단계 기준점의 시각(초)을 기록
5. 깜빡임이 시작되는 시점에서 시험 종료 (그 이후 완전방전까지는 판정에 필요한 정보가 거의 없어 생략)

### 판정 기준 3단계 (실측으로 확정)

여러 차례 실험을 거치며 육안 밝기 변화를 전압 구간과 대조한 결과:

| 단계 | 전압 구간 | 육안 체감 |
|---|---|---|
| 1차 경고 (밝기 저하 시작) | 약 300mV | 어두워지지만 케이스를 덮어도 인식 가능한 수준 |
| **2차 위험 (기능 저하)** | **약 200mV** | 많이 어두워짐, 유도등으로서 기능이 떨어지는 수준 |
| 3차 (사실상 무의미) | 약 100mV 이하 | 거의 불빛 가치 없음, 이 구간부터 깜빡임 반복 |

## 실험 결과 — 충전시간별 5회

| 충전시간 | 300mV대 진입 | 200mV대(기능저하) 진입 | 20분(1200초) 시점 전압 | 법정기준(20분) 충족 |
|---|---|---|---|---|
| 1시간 | — | — (7.2분에 깜빡임/완전방전) | — | ❌ 명백히 미충족 |
| 2시간 | — | — (19.2분에 깜빡임 시작) | — | ❌ 근소 미충족 |
| 4시간 | 조기 진입 | 약 1500초 (25분) | 약 190~256mV (경계선) | ▲ 경계선 |
| 6시간 | 503초 (8.4분) | 1511초 (25.2분) | 264.9mV | ✅ 충족 |
| 8시간 | 1446초 (24.1분) | 2107초 (35.1분) | 312.1mV | ✅ 충족 (여유 있음) |

**추세**: 충전시간이 늘수록 200mV(기능저하) 도달 시점이 뒤로 밀리는 경향이 명확함. 4→6시간 구간은 거의 정체됐다가 6→8시간 구간에서 뚜렷이 개선되는 비선형 패턴을 보임(Ni-Cd 충전 곡선 특성과 일치하는 것으로 추정).

**임계전압 재현성**: "깜빡임 시작" 시점 전압이 1시간(75.0mV)·2시간(78.2mV)·4시간(약 70~75mV) 실험에서 모두 70~78mV 범위로 재현됨. 이는 충전량과 무관하게 유도등 승압회로의 물리적 최소 동작전압이 거의 고정값이라는 근거로 판단.

### 최종 확정값

```
EVAC_DISCHARGE_THRESHOLD_V = 0.30V (300mV)
```

재검토 결과, 200mV는 육안상 이미 "유도등 기능이 떨어지는 수준"으로 확인되어 정상/경보 경계로 삼기엔 이미 늦은 지점으로 판단됨. **사전예측 시스템의 목적(기능저하 전에 미리 알림)에 맞춰 300mV("어둡지만 케이스 덮어도 인식되는" 마지막 정상 구간)를 주 판정 기준으로 상향 확정.** 200mV는 2차(보조) 경보 임계값으로, 100mV대(사실상 무의미)나 75mV대(완전 깜빡임)는 판정 기준으로 채택하지 않음.

이 기준으로 재판정하면: 20분(1200초) 시점 전압이 8h(312.1mV)는 300mV 충족, 6h(264.9mV)는 미달 — **법정기준 20분 동안 안정적 정상작동을 보장하려면 8시간 이상 충전이 필요**하다는 게 더 엄밀한 결론.

## 확인 완료 vs 남은 작업

| 항목 | 상태 |
|---|---|
| 배터리 실측 스펙 확정 (1.2V 단일셀) | ✅ 완료 |
| 무납땜 tap 접촉 안정성 | ✅ 검증 완료 (로그 노이즈 없음) |
| AC 결선 및 통전 | ✅ 완료 |
| 방전시험 프로토콜 확립 | ✅ 완료 (3단계 판정 기준) |
| `EVAC_DISCHARGE_THRESHOLD_V` 확정 | ✅ 완료 (0.30V) |
| 물리 방전시험 버튼 정상화 | ⏳ 미해결 — 시리얼 커맨드로 임시 대체 중 |
| WiFi/서버 실연동 | ⏳ 미완료 — 지금까지는 WiFi 없는 디버그 코드로만 검증 |
| 나머지 3대 확장 | ⏳ tap 작업 완료, 야간 충전 중 — 완충 후 교차검증 예정 |
| CDS/멀티플렉서 제거 반영 | ✅ 코드 반영 완료 |

## 참고 — 오늘 겪은 문제들의 공통 교훈

DC 파워서플라이 시도 실패, 배터리 스펙 오판, 접촉불량 vs 심방전 구분 등 오늘 겪은 문제 대부분이 **"실측 전 가정"과 "실측 결과"가 어긋나며 발생**했습니다. 자탐1/자탐2 실험에서도 동일한 패턴(공급전압·션트저항 값, NTC 방향)이 있었던 것처럼, 이번에도 처음부터 "실물을 받아봐야 확정할 수 있다"고 알고 있던 지점들이 그대로 나타난 것 — 예상 밖의 사고가 아니라 정상적인 검증 과정입니다.
