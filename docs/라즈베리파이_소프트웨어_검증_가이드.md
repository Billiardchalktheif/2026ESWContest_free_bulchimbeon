# 라즈베리파이 소프트웨어 검증 가이드 (실물 도착 전, Windows 기준)

> 라즈베리파이 실물이 없어도, **서버 코드(판정 로직·DB·대시보드)는 지금 노트북에서 미리 검증할 수 있습니다.** MOCK_MODE로 가짜 센서 데이터를 흘려보내면서, 서버가 제대로 판단하고 화면에 표시하는지 확인하는 과정입니다. 앱 설정할 때 했던 "처음부터 시작하기_Windows.md"랑 비슷한 흐름이에요.

---

## 0. 지금 뭘 확인하려는 건지 (30초 요약)

```
[가짜 센서 데이터] → [서버(main.py)가 받음] → [판정(rules/regression/classify)] → [DB 저장]
                                                                          ↓
                                              [대시보드(브라우저)] + [LCD/부저는 콘솔 로그로 대체]
```

실물 라즈베리파이가 오면 확인할 건 "LCD 화면이 진짜 잘 보이나, 부저 소리가 나나" 같은 **물리적 확인**뿐이고, **"판정 로직 자체가 맞게 짜여있나"는 지금 노트북으로 100% 검증 가능**합니다.

---

## 1. 준비물

- 친구가 준 `server/` 폴더 전체 (main.py, config.py, receiver/, storage/, judge/, dispatch/ 등)
- Windows PC (Python 설치 여부는 아래에서 확인)

---

## 2. Python 설치 확인

```powershell
python --version
```
버전이 뜨면 통과. 안 뜨면 https://www.python.org/downloads/ 에서 설치 (설치 시 **"Add Python to PATH"** 체크박스 꼭 체크).

---

## 3. 서버 폴더 준비

```powershell
mkdir C:\bulchimbeon\server
```
받은 `server/` 폴더 안의 모든 파일·폴더를 `C:\bulchimbeon\server\`에 그대로 복사합니다 (폴더 구조까지 통째로 — `receiver/`, `storage/`, `judge/` 등 하위 폴더 유지).

---

## 4. 필요 패키지 설치

`소프트웨어_구성안_v3.md`에 나온 구성 기준으로 최소한 이 정도는 필요합니다:

```powershell
pip install flask scikit-learn numpy joblib
```

만약 친구가 `requirements.txt` 파일을 같이 줬다면, 그걸로 한 번에 설치하는 게 더 정확합니다:
```powershell
cd C:\bulchimbeon\server
pip install -r requirements.txt
```

**설치 중 에러 뜨면**: 에러 메시지 그대로 복사해서 물어보세요 — 대부분 패키지명 오타이거나 Python 버전 호환 문제입니다.

---

## 5. MOCK_MODE 켜기

`config.py` 파일을 메모장이나 VS Code로 열어서, MOCK_MODE 관련 설정을 찾습니다 (앱 API 문서에서 `MOCK_MODE=True`로 되어 있던 것과 같은 패턴일 가능성이 높습니다):

```python
MOCK_MODE = True   # 실물 센서 없이 가짜 데이터로 서버·판정 로직만 검증
```

이 값이 `True`인지 확인하고, 아니면 `True`로 바꿔서 저장합니다.

**만약 `simulate/dummy_generator.py`처럼 별도 가짜 데이터 생성 스크립트가 있다면**, 그것도 같이 실행해야 할 수 있습니다 (아래 7단계 참고).

---

## 6. 서버 실행

```powershell
cd C:\bulchimbeon\server
python main.py
```

정상이면 이런 식의 로그가 뜹니다 (정확한 문구는 친구 코드에 따라 다를 수 있음):
```
[불침번 서버] MOCK_MODE=True
UDP 리시버 시작 - 포트 9000 대기 중
데이터베이스 연결됨: db/bulchimbeon.db
```

**이 창은 계속 켜두세요** — 닫으면 서버가 꺼집니다.

---

## 7. 가짜 데이터 흘려보내기 (필요한 경우)

MOCK_MODE가 서버 스스로 가짜값을 만드는 방식이면 6단계만으로 충분합니다. 만약 별도 실행이 필요한 구조라면(예: `simulate/dummy_generator.py`가 따로 있는 경우), **새 PowerShell 창을 하나 더 열어서**:

```powershell
cd C:\bulchimbeon\server
python simulate\dummy_generator.py
```

이렇게 두 창을 동시에 띄워두면, 하나는 서버, 하나는 가짜 센서 역할을 합니다.

---

## 8. 대시보드 확인 (브라우저)

브라우저에서:
```
http://localhost:5000
```
(포트 번호는 대시보드 코드에 지정된 값 확인 필요 — 앱 API가 5001을 썼으니 대시보드는 다른 포트일 가능성이 높습니다. 서버 실행 로그에 "Running on http://..." 같은 문구가 뜨면 그 주소 그대로 쓰면 됩니다)

5개(또는 6개) 설비 카드가 뜨고, 상태(정상/주의/경보) 색상이 표시되면 성공입니다.

---

## 9. LCD/부저 출력 확인 — 콘솔 로그로 대체

실물 LCD·부저가 없으니, `dispatch/lcd_buzzer_output.py`의 `trigger_alert()` 함수가 실제 하드웨어 제어 대신 **콘솔에 로그를 찍도록** 되어있는지 확인합니다. 만약 실물 GPIO 코드만 있고 로그 출력이 없다면, 아래처럼 임시로 print문을 추가해서 테스트할 수 있습니다:

```python
def trigger_alert(module, level, message):
    # 실물 LCD/부저 제어 코드는 그대로 두고, 위에 로그만 추가
    print(f"[알림 시뮬레이션] {module} - {level}: {message}")
    # ... 기존 GPIO 제어 코드 ...
```

이렇게 하면 "판정 결과가 맞을 때 알림 로직이 정확히 발동하는가"를 실물 없이도 확인할 수 있습니다.

## 10. 확인 체크리스트

- [ ] `python main.py` 실행 시 에러 없이 서버 시작
- [ ] 대시보드(브라우저)에서 설비 카드들이 정상/주의/경보 색상으로 표시됨
- [ ] 가짜 데이터가 시간이 지나며 계속 갱신되는 것이 대시보드에 반영됨
- [ ] 판정 임계값(예: 가스계 10%, 수계 성능시험 기준)을 넘는 가짜값을 넣었을 때 "경보" 상태로 정확히 전환되는지
- [ ] 콘솔에 알림(LCD/부저 대체) 로그가 뜨는지
- [ ] DB 파일(`db/bulchimbeon.db`)이 생성되고 데이터가 쌓이는지 (SQLite 뷰어나 `sqlite3` 명령으로 확인 가능)
