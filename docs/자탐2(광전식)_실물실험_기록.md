# 자탐2(광전식/연기구역) 실물 실험 — 오늘의 기록

> 루프저항 열화 회로(자탐1과 동일 설계) + MQ-2 가스센서 + DHT22 온습도센서를 브레드보드에 조립하고 작동 확인한 세션입니다.

---

## 오늘 한 것

- 루프저항 열화 감지 회로(자탐1과 동일 부품·구조) 조립
- MQ-2 가스센서, DHT22 온습도센서 조립
- ESP32 DevKitC에 `fire_alarm_photoelectric_node.ino` 업로드
- 시리얼 모니터로 값 확인 및 MQ-2 반응성 테스트

## 최종 배선 내역

### 루프저항 열화 회로
자탐1과 완전히 동일한 구조 재사용:
```
ESP32 5V ──[220Ω 고정저항]──[가변저항(0~1kΩ)]──[100Ω 고정저항]── GND
                                    │(wiper)              │
                              (한쪽 끝 핀 사용)      ADS1115 A1로 분기
```

### MQ-2 가스센서 (3핀, JST 커넥터)
```
빨강 → ESP32 3.3V (VCC, 실측 3.3V 확인됨)
검정 → ESP32 GND
파랑 → ADS1115 A0 (신호/AO, 실측 1~2V 확인됨)
```
- 핀에 라벨 인쇄가 없어 색상 기준으로 배선, **멀티미터 실측으로 각 선의 정체를 확정**함

### DHT22
```
빨강 → ESP32 3.3V (VCC)
검정 → ESP32 GND
초록 → ESP32 GPIO4 (신호, 디지털 단일선)
```

### ADS1115
```
SDA → ESP32 GPIO21
SCL → ESP32 GPIO22
```

## 발견한 점 (트러블슈팅 기록)

### ① 코드 상수 수정 — 자탐1과 동일하게 필요
```cpp
// 수정 전 (placeholder)
const float SUPPLY_VOLTAGE = 24.0;
const float SHUNT_OHM = 10.0;

// 수정 후 (실제 회로값)
const float SUPPLY_VOLTAGE = 5.0;
const float SHUNT_OHM = 100.0;
```

### ② MQ-2 핀이 3개뿐이라 DO(디지털출력) 자체가 없는 구성
당초 4핀(VCC/GND/AO/DO)을 전제로 확인하려 했으나, 실제 모듈은 **VCC/GND/AO(아날로그) 3핀 구성**이었음. 핀 라벨 인쇄가 없어 색상(빨강/검정/파랑)만으로 판단해야 했음.

**확인 방법**: 멀티미터로 각 선의 GND 대비 전압 실측
- 빨강: 3.3V 고정 → VCC 확정
- 파랑: 1~2V (중간값) → 신호선(AO) 확정
- 검정: GND로 간주(별도 실측은 생략, 표준 배치상 신뢰)

### ③ 초기 반응성 테스트에서 판단 어려움 (라이터 가스)
**증상**: 라이터 가스(불꽃 없이 분사)를 여러 차례 시도했으나, MQ2raw 값이 13100~13600 사이에서 노이즈 수준(±50~100)으로만 흔들리고 뚜렷한 반응 패턴이 안 보임.

**당시 진단**: 배선 문제(AO/DO 핀 착오)를 의심해 멀티미터로 재검증했으나, 배선 자체는 처음부터 정상이었던 것으로 확인됨(②의 실측 결과).

**결론**: 라이터 가스(부탄) 자체가 이 센서 기준으로 약한 자극이었을 가능성이 높음 — MQ-2는 가연성 가스보다 연기·수증기성 입자에 더 민감하게 반응하는 특성으로 추정됨.

### ④ 수증기 자극 — 명확한 반응 확인, 2회 재현
**1차 시도**: 11000 → 14070까지 지속 상승
**2차 시도**: 11348 → 13588까지 지속 상승 (재현 확인)

노이즈와 달리 **한 방향으로 꾸준히 상승하는 추세**가 두 번 연속 재현되어, 확실한 센서 반응으로 판단함.

| 항목 | 상태 |

| DHT22 (온습도) | ✅ 정상 (온도 27~30도, 습도 반응 확인) |

| MQ-2 수증기 반응성 | ✅ 2회 재현 확인, 명확한 상승 패턴 |
| WiFi/서버 연동 | ⏳ 미시도 (더미 SSID 상태) |

## 실외 화재재현 3종 비교 실측 (옥상)

> 실내 밀폐 공간에서 불을 피울 수 없어 옥상(야외, 바람 있는 환경)에서 진행. 데이터 로그가 유실되어 촬영 영상 기준으로 재구성한 근사값입니다 — 오차 감안 필요.

### 측정 결과

| 시나리오 | 가스(MQ2raw) | 온도 | 습도 |
|---|---|---|---|
| 담배연기 | 12000대 | 29~30도 | 50대 중반 |
| 전자담배(수증기) | 13000~14000 | 29~30도 | 60~65% |
| 화재 재현(종이 연소) | 11000대 후반 | 35~38도 | **45%까지 하락** |

### 분석 — 습도 방향이 핵심 구분 신호로 확인됨

**습도가 시나리오별로 반대 방향으로 갈림**:
- 수증기(전자담배): 습도 **상승**(60~65%)
- 화재(연소): 습도 **하락**(45%)

이는 설계 단계에서 예상했던 가설("화재=습도 안 오르거나 하락, 조리/수증기=습도 급상승")과 정확히 일치함. **자탐2 AI(비화재보 판별)에서 습도 방향이 실제로 유효한 구분 feature임이 실측으로 확인됨.**

**온도도 확실히 구분됨**: 담배·전자담배는 29~30도(거의 안 오름), 화재는 35~38도(확실히 상승).

**가스(MQ2raw)는 세 시나리오가 뚜렷하게 구분되지 않음** — 아래 한계점 참고.

### 한계점 — 야외/바람 환경의 영향 추정

옥상 야외라는 특성상 **바람 때문에 연소 부산물이 센서 주변에 축적되지 못하고 분산**되어, MQ-2 반응이 실내 밀폐 상황보다 약하게 나왔을 가능성이 높음. 실내 환경(연기가 공간에 갇혀 농도가 축적됨)에서는 가스 수치도 더 뚜렷하게 상승할 것으로 예상되나, 안전상 실내 점화 실험은 진행하지 못함.

**시사점**: 가스(MQ2raw) 단독 feature로는 오늘 데이터 기준 세 시나리오 구분이 어려움 → 온도상승률·습도방향을 함께 보는 다변량 판정(원래 설계된 RandomForest 3-feature 방식)의 필요성이 실측으로 재확인됨.

### 활용 방향
- 3개 시나리오 실측값을 AI 학습 데이터의 기준점(anchor)으로 활용 가능 (소량이지만 방향성 검증 자료로 유효)
- "야외 실험 환경의 한계로 가스센서 반응이 제한적이었음"을 개발완료보고서 장애요인 항목 소재로 활용 가능
- 영상 기록을 프레임 단위로 재검토해 더 정밀한 수치로 재구성하는 작업 권장 (현재는 근사값)

## 다음에 해야 할 것

1. **실내(또는 밀폐 챔버) 환경에서 화재재현 재실험**
   - 옥상 야외 실험은 바람 영향으로 가스(MQ2raw) 반응이 제한적이었음
   - 안전한 밀폐 챔버(자탐1때 썼던 것과 유사)에서 재현하면 가스 수치도 뚜렷한 차이를 보일 가능성 높음
2. **오늘 영상 기록을 프레임 단위로 재구성** — 데이터 로그 유실로 현재는 근사값, 정확한 수치로 재정리하면 AI 학습 데이터 품질 향상
3. **MQ-2 자극 종류별 반응 데이터 축적**
   - 수증기(가습기 등) 반응 재현성 있음 확인됨 — 향후 정식 데이터 수집(fire/cooking/normal 라벨링) 시 이 자극으로 진행
   - 라이터 가스 대신, 실제 발연원(향 등 연소성 연기)으로도 반응성 한 번 더 확인 권장 — 진짜 "화재" 상황 재현에 필요

2. **온도/습도 회귀분석 로직과 연계 확인**
   - 오늘 DHT22 습도값이 수증기 노출 시 어떻게 변하는지도 같이 기록해두면, 나중에 "화재 vs 조리수증기" 구분 학습 데이터로 바로 활용 가능

3. **WiFi/서버 실연동**
   - `WIFI_SSID`, `WIFI_PASS`, `SERVER_IP`를 실제 값으로 교체
   - 라즈베리파이 `main.py` 수신 확인

4. **디버그 출력 정리**
   - 임시로 추가한 `Serial.printf(...)` 줄 — 정식 검증 끝나면 제거 또는 주석 처리 고려
