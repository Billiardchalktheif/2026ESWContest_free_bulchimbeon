# 네이티브 앱, 이게 뭔지부터 — 팀 미팅용 쉬운 설명

> 오늘 팀 모여서 앱 개발 얘기할 때 쓸 자료예요. 코딩 몰라도 이해되게 비유로 풀었습니다. 실제 설치·개발 방법은 앱 담당 친구가 준 가이드(`처음부터_시작하기_Windows.md`, `네이티브앱_고급기능_가이드.md`)를 따로 보면 됩니다 — 이 문서는 "그게 대체 뭘 하는 건지" 큰 그림만 잡는 용도예요.

---

## 1. 네이티브 앱이 뭔지

폰에 설치해서 쓰는 "진짜 앱"이에요. 카카오톡, 인스타그램처럼 **앱스토어/플레이스토어에서 다운받아 아이콘 눌러서 여는 것**이 네이티브 앱입니다.

**비유**: 웹사이트(브라우저로 보는 것)는 "식당에 배달 주문하는 것"이고, 네이티브 앱은 "우리 집 냉장고에 직접 재료 채워놓고 요리하는 것"이에요. 배달(웹)은 매번 인터넷으로 다시 받아와야 하지만, 냉장고(앱)는 폰 안에 이미 들어있어서 반응이 빠르고, 폰 기능(알림, 카메라, GPS 등)도 더 자유롭게 쓸 수 있어요.

## 2. 왜 굳이 네이티브 앱을 만드는지

우리 프로젝트는 원래 **대시보드(컴�터/노트북 화면)**로도 다 볼 수 있어요. 근데 앱을 따로 만드는 이유는:

- **알림이 폰으로 바로 옴** — 컴퓨터 화면 안 보고 있어도 "소화기 이탈 감지!" 같은 경고가 폰에 뜸
- **QR코드 스캔** — 소화기에 붙인 QR을 폰 카메라로 찍으면 바로 그 설비 정보가 뜸 (이건 웹으로는 좀 불편하고 앱이 훨씬 자연스러움)
- **시연 임팩트** — 발표할 때 "폰으로 이렇게 확인합니다"라고 보여주면 실감 남

## 3. Flutter가 뭔지 (우리가 쓸 도구)

**Flutter(플러터)** = 앱을 만드는 도구(프레임워크)예요. 구글이 만든 거고, 요즘 많이 씀.

**비유**: 레고 블록 세트라고 생각하면 돼요. 원래 안드로이드 앱이랑 아이폰 앱은 **완전히 다른 언어로, 따로따로** 만들어야 했어요(안드로이드는 코틀린, 아이폰은 스위프트). 근데 Flutter는 **레고 블록 한 세트로 안드로이드 집도 짓고 아이폰 집도 지을 수 있게** 해주는 도구예요 — 코드를 한 번만 짜면 두 플랫폼에 다 쓸 수 있어요.

우리는 시간이 없으니까, **안드로이드용으로만** 먼저 만들 거예요(아이폰까지 하면 시간이 배로 들어요).

## 4. 앱이 우리 프로젝트에서 하는 일 (핵심 개념 하나)

앱은 사실 어렵게 생각할 거 없이, **"라즈베리파이한테 물어보고 답 받아서 화면에 보여주는 것"**이 전부예요.

**비유**: 앱은 "심부름꾼"이에요.
1. 앱이 라즈베리파이(서버)한테 "지금 소화기 상태 어때?" 하고 물어봄
2. 라즈베리파이가 "정상이야" 또는 "이탈됐어!" 하고 답을 줌
3. 앱이 그 답을 폰 화면에 예쁘게 보여줌

이렇게 "물어보고 답 받는" 방식을 **API**라고 불러요. 우리는 이미 라즈베리파이 쪽에 이 "질문 받는 창구"(API)를 몇 개 만들어뒀어요(`/api/status`, `/api/history` 등). 앱은 그냥 이 창구에 물어보기만 하면 되는 거라, **앱 담당자가 서버 코드를 몰라도 개발 가능**해요.

## 5. 개발 환경, 대충 뭘 까는 건지

기술 가이드(`처음부터_시작하기_Windows.md`)에 자세히 나오겠지만, 큰 그림만 말하면:

1. **Flutter SDK** — 레고 블록 세트 자체를 다운로드
2. **Android Studio(또는 VS Code)** — 블록 조립할 작업대(편집기)
3. **에뮬레이터(가상 폰)** — 실제 폰 없어도 컴퓨터 화면에 가짜 폰 화면을 띄워서 테스트 가능

이 세 개만 깔면 "빈 화면에 글자 하나 띄우기" 정도는 바로 시작할 수 있어요.

## 6. 오늘 미리 봐두면 좋을 것 — 핫리로드(Hot Reload)

Flutter의 제일 편한 기능인데, **코드를 고치자마자 화면이 바로 바뀌는 걸 눈으로 확인** 할 수 있어요.

**비유**: 원래는 요리하면(코드 수정) 다 만들고 나서야 맛볼 수 있는데(처음부터 다시 실행), 핫리로드는 **간을 보면서 그 자리에서 바로바로 양념을 조절**하는 거예요. 이게 있어서 앱 개발이 생각보다 빠르게 진행될 수 있어요.

## 7. 오늘 팀 미팅에서 정할 것들

- [ ] **화면 몇 개 만들지** — 예: 홈(상태요약), 알림 목록, QR스캔, 설정 정도로 3~4개
- [ ] **어떤 기능부터 만들지 우선순위** — 앞서 정리했던 것 중 QR코드 조회 + PDF 리포트가 가성비 좋다고 했었음
- [ ] **API 명세 확인** — 서버 쪽 `/api/status` 등이 정확히 어떤 데이터를 주는지, 서버 담당 친구랑 맞춰보기
- [ ] **일정** — 예선(9월 초)까지 어디까지 만들지, 안 되면 결선으로 미룰 기능 정하기

## 8. 이것만 기억하면 됨 (한 줄 요약)

> **"앱은 라즈베리파이한테 물어보고 답을 화면에 예쁘게 보여주는 심부름꾼. Flutter는 그 심부름꾼을 만드는 레고 블록 세트."**

이 정도 그림만 잡고, 세부 설치·코딩은 앱 담당 친구가 준 가이드 따라가면 될 것 같아요.
