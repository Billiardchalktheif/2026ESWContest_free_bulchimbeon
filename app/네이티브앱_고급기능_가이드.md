# 불침번 — 앱 고급 기능 가이드 (QR / PDF / 원격 성능시험)

우선순위 제안하신 대로 구현했습니다: **QR조회 + PDF리포트**를 핵심으로, **원격 성능시험 트리거**, 그리고 가벼운 **경보 확인/부저 음소거**까지 붙였습니다. 역할구분/다크모드/위젯/TTS는 말씀하신 것처럼 보너스 티어라 지금은 안 넣었고, 시간 남으면 이 문서 맨 아래 "다음 단계"에 어디를 건드리면 되는지 적어뒀습니다.

---

## 새로 추가된 것 요약

| 기능 | API 엔드포인트 | 앱 화면 |
|---|---|---|
| QR 스캔 → 설비 이력 조회 | `GET /api/equipment/<qr_id>` | QR조회 탭 |
| PDF 점검이력 리포트 | `GET /api/report/pdf?days=30` | 도구 탭 |
| 수계 원격 성능시험 트리거 | `POST /api/performance-test/trigger` | 도구 탭 |
| 경보 확인(Ack) | `POST /api/alerts/<id>/ack` | 알림 탭 (각 항목 "확인" 버튼) |
| 부저 원격 음소거 | `POST /api/buzzer/mute` | 알림 탭 (상단 스피커 아이콘) |

앱 탭이 기존 2개(상태/알림)에서 **4개(상태/QR조회/알림/도구)**로 늘었습니다.

## 1. 서버 쪽 추가 설치

```bash
pip install reportlab --break-system-packages   # PDF 생성용
pip install "qrcode[pil]" --break-system-packages  # QR 이미지 생성용 (한 번만 실행하면 됨)
```

## 2. QR코드 만들어서 출력하기

```bash
python generate_qr_codes.py
```
`qr_codes/` 폴더에 `EXT-01.png` ~ `EXIT-04.png` 8개가 생깁니다. 이걸 인쇄해서 소화기 4개, 유도등 4개에 하나씩 붙이면 됩니다 (3~4cm 크기, 코팅 추천).

**중요**: QR코드 안에는 `EXT-01` 같은 짧은 문자열만 들어있습니다. 이 ID는 `server/api.py`의 `EQUIPMENT_REGISTRY`에 있는 것과 정확히 일치해야 인식됩니다. 실제 설비 위치(1층 로비, 2층 복도 등)로 이름을 바꾸고 싶으면 그 딕셔너리만 수정하면 됩니다.

## 3. Flutter 쪽 추가 설정 — 카메라 권한

QR 스캔은 카메라 권한이 필요해서, `flutter pub get` 하고 나서 아래 파일을 직접 수정해야 합니다.

**Android** — `android/app/src/main/AndroidManifest.xml`의 `<manifest>` 태그 안에 추가:
```xml
<uses-permission android:name="android.permission.CAMERA" />
```

**iOS** (시연용이면 스킵 가능, 아이폰으로 테스트할 때만) — `ios/Runner/Info.plist`에 추가:
```xml
<key>NSCameraUsageDescription</key>
<string>QR코드 스캔을 위해 카메라 접근이 필요합니다</string>
```

이후 평소처럼:
```bash
flutter pub get
flutter run
```

## 4. 시연 시나리오 추천

1. **상태 탭** 먼저 보여주기 — 6개 구역 실시간 카드
2. **QR조회 탭**으로 이동, 인쇄해둔 소화기 QR코드 실제로 스캔 → 이력 화면 뜨는 것 보여주기 (여기가 제일 시각적 임팩트)
3. **도구 탭**에서 "PDF 생성" 버튼 눌러서 리포트 다운로드되는 것 보여주기 — "관리사님이 이 자료를 증빙으로 쓸 수 있다"는 멘트와 함께
4. **도구 탭**에서 "시험 시작" 버튼 눌러서, 동시에 팀원이 옆에서 니들밸브 조작하는 장면 — "폰으로 원격 트리거 + 현장 조작이 결합된 반자동 시스템" 설명
5. **알림 탭**에서 경보 확인 버튼, 음소거 버튼 시연

## 5. 원격 성능시험에 대해 정직하게 짚어야 할 부분

지금 하드웨어 설계상 **니들밸브는 수동 조작**이에요 (조립가이드에 명시됨). 그래서 이 기능은 "완전 원격시험"이 아니라 **"펌프 기동/측정은 원격, 밸브 개폐는 현장"인 반자동**입니다. 발표 때 이 부분을 숨기지 말고 오히려 "솔레노이드 밸브로 교체하면 완전 자동화 확장이 가능하다"는 로드맵으로 설명하면, 과장 없이도 충분히 인상적이에요.

실제로 완전 자동까지 가려면 두 가지가 더 필요합니다:
- 니들밸브 → 솔레노이드 밸브 교체
- `server/api.py`의 `trigger_performance_test()` 함수가 실제로 ESP32에 UDP 명령(`run_test`)을 보내고, ESP32 쪽 `.ino` 코드에 그 명령을 받아서 릴레이/밸브를 조작하는 리스너를 추가해야 함 (지금은 `mock_run_pump_sequence()`로 흉내만 냄)

## 6. 다음 단계 (시간 남으면, 우선순위 낮은 것부터)

- **경보 확인/음소거를 실제 DB에 영구 저장** — 지금은 서버 재시작하면 메모리에 있던 확인 상태가 날아감. `db/`에 컬럼 하나(`acknowledged`)만 추가하면 됨
- **역할 구분(관리자/조회전용)** — 제일 간단한 방법은 앱에 로그인 없이 "관리자 모드 진입 시 4자리 PIN 입력" 정도로 흉내내는 것. 진짜 인증서버까지는 시간 대비 과함
- **다크모드** — `ThemeData`를 `ThemeMode.system`으로 바꾸고 다크 컬러셋 하나 추가하면 끝, 30분이면 됨
- **홈화면 위젯** — Android는 `home_widget` 패키지, iOS는 별도 위젯 익스텐션 필요해서 이건 시간이 꽤 듦. 우선순위 제일 낮게 두는 걸 추천
- **TTS 음성 알림** — `flutter_tts` 패키지로 경보 메시지 읽어주기, 알림 탭에 새 경보 뜰 때 트리거하면 됨. 반나절 정도 소요 예상
