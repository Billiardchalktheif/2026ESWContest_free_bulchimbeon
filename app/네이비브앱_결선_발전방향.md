# 불침번 앱 — 결선 발전방향 (오늘 미룬 항목 정리)

> 예선 제출(9/3) 기준 QR→설비상세(통짜 대시보드)→점검완료→PDF 풀 플로우는 완성.
> 아래 6개는 시간상 오늘 스킵하고 결선에서 이어갈 항목.

---

## 1. 앱 아이콘 커스텀 이미지 적용
현재 Flutter 기본 아이콘 그대로 사용 중. `flutter_launcher_icons` 패키지로 교체 예정이었으나 작업량 대비 우선순위 낮아 보류.
- 필요 작업: 1024x1024 정사각 로고 준비 → `assets/icon/icon.png` → `pubspec.yaml`에 `flutter_launcher_icons` 설정 → `flutter pub run flutter_launcher_icons` 실행 → 앱 완전 재설치

## 2. PDF 한글 폰트 적용
PDF 생성 시 한글이 전부 네모(□)로 깨짐. `pdf` 패키지 기본 폰트가 한글 미지원이라 발생.
- 필요 작업: Noto Sans KR 등 한글 폰트(.ttf)를 `assets/fonts/`에 추가 → `pubspec.yaml` 에셋 등록 → `settings_screen.dart`의 `_generatePdf`에서 `rootBundle.load`로 폰트 로드 후 모든 `pw.Text`/`pw.Table` 스타일에 `font:` 명시

## 3. 점검이력 영구 저장
현재 `inspection_api.py`의 `today_inspections`는 파이썬 메모리 리스트라 **서버 재시작 시 전부 소실**됨. 실서비스 전환 시 필수.
- 필요 작업: SQLite(대시보드가 쓰는 DB와 별도 테이블 권장) 또는 파일 기반 저장으로 교체. 점검이력 조회 시 날짜 범위 필터링 로직도 함께 설계 — 데이터가 누적되면 PDF 요청 시 전체 이력이 한 번에 뽑히는 걸 방지해야 함(기본은 "오늘"/"최근 N일"로 제한, 전체 조회는 명시적 선택 시에만).

## 4. 홈화면 상태 리스트 실시간 자동 폴링
현재는 앱 진입/탭 전환 시점에만 상태를 새로 불러옴(수동 새로고침 개념). 화면을 계속 보고 있는 동안 상태가 바뀌어도 반영 안 됨.
- 필요 작업: `Timer.periodic`으로 일정 주기(예: 10~30초)마다 `_fetchStatus()` 자동 재호출, `dispose()`에서 타이머 정리 필수 (메모리 누수 방지)

## 5. 대시보드 개별 설비 라우트 추가 → QR 역할 재정의
현재 Flask 대시보드(`dashboard/app.py`)는 `/` 라우트 하나에 6개 설비를 통짜로 렌더링. 개별 설비만 필터링해서 보여주는 라우트가 없어서, 앱의 QR스캔과 홈화면 리스트 탭이 **똑같은 통짜 화면**으로 연결됨 — QR을 찍으나 안 찍으나 결과가 같아 QR의 실질적 효용이 낮음.
- 필요 작업: `dashboard/app.py`에 `/equipment/<equipment_id>` 형태 라우트 신설, 기존 6개 설비 카드 렌더링 로직에서 해당 설비만 필터링해 반환. 기존 `/` 라우트와 렌더링 함수(`get_fire_alarm_cards` 등)는 그대로 두고 재사용. 완료 후 앱의 `equipment_detail_screen.dart` WebView URL을 통짜(`/`)에서 `/equipment/{id}`로 전환하면, QR이 "그 설비만 바로 보여주는" 진짜 필터링 진입점 역할을 하게 됨.

## 6. 홈화면 체크리스트 — 실제 DB 상태 연동
**현재 가장 우선순위 높은 항목.** `inspection_api.py`의 `/api/equipment/checklist`가 하드코딩된 더미 데이터를 반환 중 (`{"equipment_id": "detector2_zone_b", "status": "normal"}` 등 고정값). 실제 대시보드 DB에서는 자탐2가 alarm 상태여도 앱 홈화면 배너는 계속 normal로 표시되는 불일치 확인됨.
- 필요 작업: `inspection_api.py`가 대시보드와 같은 SQLite DB(`config.DB_PATH`)를 직접 조회하도록 수정. `dashboard/app.py`의 `get_fire_alarm_cards`, `get_water_pump_card`, `get_gas_cards`, `get_extinguisher_cards`, `get_evac_light_cards` 판정 로직을 참고해 각 설비의 최신 status만 요약 추출하는 함수 신설. 기존 대시보드 코드는 건드리지 않고, `inspection_api.py`에서 읽기 전용으로 같은 DB에 접근만 하면 됨(쓰기 충돌 없음).

---

## 우선순위 제안 (결선 착수 시)

1. **6번 (홈화면 실제 DB 연동)** — 가짜 데이터가 화면에 그대로 노출되는 건 신뢰도 문제로 직결, 최우선
2. **5번 (개별 설비 라우트 + QR 역할 회복)** — 시스템 설계상 QR의 존재 이유를 살리는 핵심 개선
3. **3번 (영구 저장)** — 실서비스 전제 조건
4. 4번, 2번, 1번 — 완성도/UX 개선, 상대적으로 후순위
