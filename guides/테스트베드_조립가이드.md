# 불침번 테스트베드 조립 가이드

> 순서대로 따라 하면 되는 실전 조립 순서예요. 각 모듈은 독립적으로 만들고, 하나씩 완성해서 단독 테스트한 다음에 전체를 합치는 순서를 추천해요 — 한 번에 다 연결하면 문제 생겼을 때 원인 찾기 힘들어요.

**공통 원칙**
1. 센서 하나 배선할 때마다 멀티미터로 전압/연속성 확인
2. ESP32에 코드 올려서 시리얼 모니터로 값 찍어보고 정상인지 확인 후 다음 부품으로 넘어가기
3. 브레드보드에서 먼저 완성 → 문제없으면 그 다음에 케이스/마운팅 작업

---

## 1. 자탐1 — 차동식구역

**조립 순서**
1. 소형 브레드보드에 ESP32 DevKitC 꽂기
2. ADS1115를 브레드보드에 꽂고 ESP32와 연결: `SDA→GPIO21`, `SCL→GPIO22`, VCC→3.3V, GND→GND
3. 고정저항 2개로 분압 회로 구성 → TS0202 온도센서 AO 출력을 ADS1115 채널 A0에 연결
4. 감지기 모형 2개 + 고정저항으로 루프 회로 하나 구성 → ADS1115 채널 A1에 연결 (감지기 모형은 그냥 저항 역할이라 직렬로 이어서 배치)
5. 투명 아크릴 챔버(2차 항목) 안에 TS0202 온도센서와 감지기 모형을 넣고, 챔버 옆에서 열풍기를 쐴 수 있게 배치
6. ESP32 코드 업로드 후 열풍기 켜보면서 A0 값이 실시간으로 오르는지 확인

**배치 포인트**: TS0202는 열풍기 바람이 직접 닿는 위치에, 감지기 모형은 챔버 안 아무 곳(장식 역할)에 두면 돼요.

---

## 2. 자탐2 — 광전식(연기)구역

**조립 순서**
1. 브레드보드에 ESP32 DevKitC + ADS1115 (1과 동일하게 I2C 연결)
2. MQ-2 가스센서 AO → ADS1115 채널 A0
3. DHT22 → ESP32 GPIO4 (디지털 단일선 방식)
4. 감지기 모형 2개 + 고정저항 루프 → ADS1115 채널 A1
5. 별도 챔버(자탐1과 별개 공간)에 MQ-2, DHT22, 감지기 모형 배치
6. 가습기/전기포트, 발연원(향)을 챔버 근처에 준비 — 시연 시 챔버 안으로 증기/연기를 넣을 수 있게

**배치 포인트**: MQ-2는 가스가 잘 닿는 챔버 중앙, DHT22는 습도 변화를 잘 감지할 수 있는 위치(구석 말고 공기 흐름 있는 곳)에 두세요.

---

## 3. 수계 — 성능시험 + AI 검증

**배관 조립 (먼저)**
1. 미니 탱크에 물 채우기, 워터펌프 2개(충압용/주펌프용)를 탱크 안에 담금
2. 각 펌프 출수구에 실리콘 호스 연결
3. 한쪽 호스 라인 중간을 잘라서 **T피팅(G1/4)** 삽입 → 위쪽 암나사에 **G1/4 압력센서** 장착 (테프론테이프로 나사부 밀봉)
4. 같은 라인 또는 다른 라인에 **니들밸브** 설치 (체절/부하 전환용) — 케이블타이로 호스와 피팅 고정

**전기 배선**
5. 브레드보드에 ESP32 DevKitC
6. 릴레이 모듈(2채널): CH1↔충압펌프, CH2↔주펌프 — 릴레이 트리거핀은 ESP32 GPIO25/26, 전력측(COM/NO)에 12V 어댑터+펌프선 연결
7. **INA219 2개**를 각 펌프 전원선 **중간에 끊어서 직렬로 삽입** (⚠️ CT클램프처럼 감싸기만 하면 안 됨 — DC는 CT클램프로 측정 불가해서 INA219로 교체함): 릴레이 NO → INA219 Vin+, INA219 Vin- → 펌프(+). SDA→ESP32 GPIO21, SCL→GPIO22 (두 모듈 I2C 버스 공유, 단 A0 패드로 주소 다르게 설정: #1은 기본 0x40, #2는 A0→VCC 점퍼로 0x41)
8. 압력센서 3선(빨강=VCC→5V, 검정=GND→GND, 초록=Signal→저항분압 후 GPIO32)

**동작 테스트**
9. 니들밸브 완전히 잠금 → 릴레이로 펌프 켜기 → 압력센서 값이 오르다가 멈추는 지점(체절압) 확인
10. 니들밸브 열기 → 펌프 작동 중 압력값(부하압) 확인
11. 이 순간 INA219로 읽은 전류값도 같이 기록해두기 (나중에 AI 학습용 라벨 데이터가 됨)

**⚠️ 제일 먼저 확인할 것**: 체절 상태 전류가 실제로 부하 상태보다 높게 나오는지 낮게 나오는지 — 이 결과에 따라 AI 라벨링 방향이 정해져요.

## 4. 가스계 소화설비 (CO2 소화설비)

**조립 순서**
1. 로드셀(보유 재고) 2개를 평판 양 끝에 배치 — 한쪽 끝은 고정 프레임에, 다른 쪽 끝(하중측)에 작은 받침판을 얹는 구조
2. 두 로드셀의 같은 극성 단자끼리 병렬 연결(E+끼리, E-끼리, S+끼리, S-끼리)
3. 그 묶음을 HX711 1개에 연결 (E+/E-/S+/S− → HX711 해당 핀)
4. HX711 DT→GPIO16, SCK→GPIO17, VCC→3.3V, GND→GND
5. 받침판 위에 미니어처 CO2 용기 모형(또는 임의의 물체) 올리기
6. 코드 업로드 후 영점(0점) 캘리브레이션 — 아무것도 안 올린 상태에서 0으로 맞추기
7. 알고 있는 무게(동전, 저울로 잰 물건 등)를 올려서 실제 무게와 센서값이 맞는지 스케일 보정
8. **공병중량 별도 측정·저장** — 용기만 단독으로(약제 없이) 올려서 나온 값을 `공병중량`으로 코드에 상수 저장 (또는 미니어처 용기 자체 무게를 별도로 재서 기록)
9. 판정 임계치는 **약제중량 기준** 10% 손실로 설정 (출처: 소방시설등 점검관리 매뉴얼 — 이산화탄소소화설비 점검표, "이산화탄소는 중량 손실 10% 미만")

**⚠️ 계산 시 주의 — 총중량이 아니라 약제중량 기준**
받침판에 얹힌 총중량(용기+약제)을 그대로 "초기값 대비 %"로 계산하면, 용기 자체의 고정된 무게 때문에 손실률이 실제보다 작게 나오는 오류가 생깁니다. 반드시 아래처럼 공병중량을 뺀 약제중량만으로 계산하세요.

```python
# server/judge/rules.py (가스계 판정 로직)
EMPTY_CONTAINER_WEIGHT = 0.0  # 캘리브레이션 8단계에서 측정한 공병중량(g), 코드에 상수로 저장

def co2_loss_ratio(current_total_weight, initial_total_weight):
    initial_agent_weight = initial_total_weight - EMPTY_CONTAINER_WEIGHT
    current_agent_weight = current_total_weight - EMPTY_CONTAINER_WEIGHT
    loss_ratio = (initial_agent_weight - current_agent_weight) / initial_agent_weight * 100
    return loss_ratio  # 10% 이상이면 재충전 판정
```

**배치 포인트**: 용기가 받침판 중앙에 오도록 놓아야 두 로드셀이 하중을 균등하게 나눠 받아요.

## 5. 소화기

**리프노드 4개, 아래 과정을 각각 반복**
1. ESP32-C3 SuperMini에 MPU6500 연결: SDA→GPIO8, SCL→GPIO9, INT→GPIO2
2. LiPo 배터리(PH2.0) → TP4056 승압모듈의 B+/B- 단자에 꽂기
3. TP4056의 SH1.25 출력(5V) → 매칭 케이블로 ESP32-C3의 5V/GND 핀에 연결
4. (2차 옵션) FSR 압력패드는 GPIO3(ADC)에 연결, 소화기 거치대 바닥에 깔기
5. ESP32-C3, MPU6500, 배터리+TP4056을 양면테이프로 소화기 본체(또는 거치대)에 부착 — 1개는 실물 소화기(보유분)에, 나머지 3개는 센서만 단독으로 리그 구성해도 됨

**게이트웨이**
6. ESP32 DevKitC 1개를 게이트웨이로 — 별도 센서 연결 없이 전원만 공급, 코드로 ESP-NOW 수신 + WiFi 송신 역할

**테스트**: 리프노드를 손으로 들어올려보면서 MPU6500 값이 튀는지, 게이트웨이가 신호를 잘 받는지 확인

## 6. 유도등

**조립 순서**
1. 브레드보드에 ESP32 DevKitC
2. CD74HC4067 연결: SIG→GPIO32, S0~S3→GPIO25,26,27,14
3. 유도등 4개 각각에 대해:
   - CDS 조도센서 AO → 멀티플렉서 채널(C0, C2, C4, C6)
   - 저항분압 회로(배터리 전압 측정용, 자탐 저항세트 재사용) → 멀티플렉서 채널(C1, C3, C5, C7)
4. 유도등 배터리는 반드시 **순정 규격(Ni-Cd, 동일 전압/용량)**으로 장착 — 다른 배터리로 대체 금지
5. 코드에서 S0~S3 조합을 바꿔가며 16개 채널 중 8개(사용 채널)를 순서대로 읽도록 구현

**배치 포인트**: 조도센서는 유도등 LED 바로 앞에 붙여야 점등 여부를 정확히 감지해요.

## 7. 전체 통합 순서

각 모듈이 개별로 잘 동작하는 걸 확인했으면:
1. 모든 ESP32 보드에 같은 WiFi 정보(SSID/비밀번호) 입력
2. 라즈베리파이에 서버 코드(UDP 수신 프로그램) 실행
3. 모듈 하나씩 전원 켜면서 서버 로그에 데이터가 들어오는지 확인 (한 번에 다 켜지 말고 순서대로)
4. 전부 확인되면 대시보드 화면 켜서 값이 제대로 표시되는지 최종 점검

## 8. 센서값은 그 다음에 어떻게 처리되나 (간단 요약)

```
센서 → ESP32 (1차 판정: 기준값 넘었는지 간단히 체크)
     → WiFi/UDP (또는 소화기는 ESP-NOW→게이트웨이→WiFi)
     → 라즈베리파이 서버
         ├─ 데이터베이스에 계속 저장 (나중에 추세 그래프용)
         ├─ 자탐/수계는 저장된 데이터를 AI 모델에 넣어서 분류 (정상/오작동, 정상/과부하 등)
         ├─ 가스계/유도등/자탐배선 등은 회귀분석으로 "언제 기준치 도달할지" 계산
         └─ 결과를 종합해서
             → 대시보드 화면에 표시 (평면도 위 정상/주의/경보 색상)
             → 이상 있으면 경고음 or 앱 알림 발송
```

**핵심만 말하면**: ESP32는 값을 재서 서버로 던지기만 하고, "진짜 판단(추세 분석, AI 분류)"은 전부 라즈베리파이에서 처리해요. ESP32는 그냥 손발이고, 라즈베리파이가 두뇌 역할이라고 보면 돼요.
