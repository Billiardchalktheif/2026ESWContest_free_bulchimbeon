## 1. 시스템 개요 — 두 가지 독립 시나리오

이 노드는 서로 다른 배관/센서를 보며 완전히 독립적으로 동작하는 두 기능을 수행한다.

| | (A) 성능시험 | (B) 충압펌프 자동제어 |
|---|---|---|
| 트리거 | 수동 (시리얼 `P` 입력) | 자동 (헤더 압력 상시 감시) |
| 대상 배관 | 주펌프 성능시험배관 | 헤더(주+충압 합류 후) |
| 사용 센서 | 압력센서①, 유량센서 | 압력센서②, INA219(충압) |
| 목적 | H-Q 곡선(라즈베리파이가 연산) | 압력강하 시 충압펌프 자동기동 + 전류파형 AI 분석 |
| 밸브 조작 | 사람이 니들밸브 수동 개폐 | 사람이 나비밸브로 미세누설/화재 흉내 |

## 2. 배관도

```
주펌프    → [분기티①] ─┬→ [체크밸브①] ─┐
                        └→ 성능시험배관A │
                          (유량센서       ├→ [합류티] → 헤더 → 압력센서②(곁가지)
                           →압력센서①    │              → 나비밸브(말단, 압력강하 시연)
                           →니들밸브)     │
                                          │
충압펌프  → [체크밸브②] ────────────────┘
```

- **성능시험배관 분기 위치**: 반드시 체크밸브보다 앞(펌프 쪽)에서 갈라져야 함. 체크밸브 뒤에서 분기하면 헤더 경로를 잠갔을 때 성능시험배관 쪽으로 물이 못 감 (NFTC 102 2.3.7 ① 기준과 동일 원리).
- **체크밸브**: 각 펌프 전용 1개씩. 정상운전(헤더) 경로에만 있고, 성능시험배관 쪽에는 없음.
- **압력센서 2개**: 성능시험배관용(①)과 헤더용(②)은 서로 다른 지점 — 겸용 불가 (성능시험 모드일 때 헤더와 물리적으로 분리되기 때문).
- **밸브 2종 역할 구분**:
  - 니들밸브 (성능시험배관): 개폐 + 유량조절, H-Q 곡선 측정용
  - 나비밸브 (헤더 말단): 개폐 전용, 압력강하(미세누설/화재) 시연용

## 3. ESP32 핀 배치

| 부품 | 핀 | 종류 | 비고 |
|---|---|---|---|
| INA219 (충압펌프, 0x40) | SDA→GPIO21, SCL→GPIO22 | I2C | 기본 주소 |
| INA219 (주펌프, 0x41) | SDA→GPIO21, SCL→GPIO22 | I2C | 동일 버스, A0 패드→VCC 점퍼로 주소 변경 |
| 릴레이 (충압펌프) | GPIO25 | 디지털 출력 | |
| 릴레이 (주펌프) | GPIO26 | 디지털 출력 | |
| 압력센서① (성능시험배관) | GPIO32 | ADC1 | 저항분압 필수 (아래 4번 참고) |
| 압력센서② (헤더) | GPIO34 | ADC1 | 저항분압 필수 |
| 유량센서 (YF-S201) | GPIO27 | 디지털 입력(인터럽트) | 홀센서 펄스, FALLING 엣지 |

**ADC1 그룹(32~39)만 사용** — ADC2는 WiFi 사용 중 불안정해지므로 압력센서는 반드시 ADC1 핀에 배정.

## 4. 배선 상세

### 4.1 전원 라인 (12V, 펌프 구동)

```
파워서플라이(+) ──┬──► 주펌프(+)
                   └──► 충압펌프(+)

파워서플라이(-) ──┬──► 릴레이(주펌프) COM
                   └──► 릴레이(충압펌프) COM

릴레이(주펌프) NO ────► INA219(0x41) Vin+ → Vin- ────► 주펌프(-)
릴레이(충압펌프) NO ──► INA219(0x40) Vin+ → Vin- ────► 충압펌프(-)
```

- INA219는 전선을 실제로 끊어서 전류 경로에 **직렬 삽입**(High-side). CT클램프처럼 감싸기만 하면 안 됨 — DC 전류라 CT클램프 방식(전자기 유도) 자체가 측정 불가.
- **각 펌프의 (-) 라인은 절대 서로 만나면 안 됨** (섞이면 릴레이 하나만 켜도 두 펌프가 동시기동하는 문제 발생 — 실측 확인됨).

### 4.2 릴레이 구동 전원 (5V)

```
5V 전원(+) ──┬──► 릴레이① VCC
             └──► 릴레이② VCC

GND ─────────┬──► 릴레이① GND
             ├──► 릴레이② GND
             ├──► INA219×2 GND
             ├──► 압력센서×2 GND
             └──► ESP32 GND (반드시 공통! 빠지면 INA219 Bus Voltage가 비정상적으로 낮게 측정됨 — 실측 확인됨)
```

### 4.3 압력센서 (×2, 0.5~4.5V 출력 → 저항분압 필수)

ESP32 ADC 안전범위(3.3V)를 넘는 신호라 반드시 분압 후 입력.

```
압력센서 Signal ──[R1 10kΩ]──┬──[R2 20kΩ]──── GND
                               │
                               └──► ESP32 GPIO32 또는 GPIO34
```

- 분압 후 실제 전압 범위: 0.5~3.0V (코드 상수 `PRESSURE_V_MIN`/`PRESSURE_V_MAX`)
- 두 압력센서 모두 동일한 분압 회로 적용
- 초기 사용 전 기포 벤팅 필요 (수평 장착 시 특히) — 물 채울 때 밸브 완전개방 후 천천히, 결합부 톡톡 쳐서 기포 제거

### 4.4 유량센서 (YF-S201)

```
유량센서 Red(VCC)   → 5V
유량센서 Black(GND) → GND
유량센서 Yellow(Signal) → ESP32 GPIO27 (INPUT_PULLUP, FALLING 인터럽트)
```

- 몸통 화살표 방향 = 흐름 방향과 일치해야 함 (역방향 장착 시 임펠러 안 돌아 값 0 고정)
- `FLOW_K_FACTOR`(현재 7.5, 데이터시트 참고값)는 체적법(비커+스톱워치) 실측 후 재조정 필요

### 5.2 캘리브레이션 필요 (실측 전까지 임시값)

| 상수 | 현재값 | 캘리브레이션 방법 |
|---|---|---|
| `JOCKEY_HEADER_START_KPA` | 400.0 (임의) | 니들밸브 살짝 열어둔 상태로 몇 분 관찰, 자연 압력 하한 근처로 설정 |
| `JOCKEY_HEADER_STOP_KPA` | 500.0 (임의) | 위와 동일, 자연 압력 상한 근처로 설정 (START보다 충분히 커야 채터링 방지) |
| `FLOW_K_FACTOR` | 7.5 (데이터시트) | 체적법 실측: 일정 시간 펄스 수 vs 비커로 받은 실제 부피 비교 |
| `PRESSURE_V_MIN` / `PRESSURE_V_MAX` | 0.5 / 3.0 | 저항분압 회로 실측 후 정확한 값으로 교체 |
| `JOCKEY_START_THRESHOLD_MA` | 50.0 (임의) | 충압펌프 정상 기동 시 실제 전류값 실측 후 그 이하로 설정 |

### 5.3 서버(라즈베리파이) — 구현 필요

**(A) 성능시험 — H-Q 곡선 연산 (`server/pump_performance_test.py`)**
- ESP32가 보내는 `pressure_kpa` + `flow_lpm` 시계열 수신
- `determine_valve_state()`: 압력값 패턴으로 체절/부하 상태를 서버가 스스로 추정해 label 부여 (ESP32는 밸브 상태를 모름 — 수동 조작이라)
- 정격토출량 대비 100%/150% 지점 등 성능시험 기준(NFTC 102 2.2.1.7)과 대조해 판정 결과 시각화

**(B) 충압펌프 자동제어 — 파형 분류 (`server/pump_classifier.py` 또는 유사)**
- ESP32가 기동 이벤트마다 보내는 `rms`, `peak`, `duty_cycle`, `actual_running`, `cycle_interval_sec` 수신
- 정상/이상(기동실패, 공회전 등) 분류 — `train_pump_classifier.py`로 학습한 모델 적용
- `cycle_interval_sec` 추세로 작동빈도 집계 → 간격이 짧아지는 추세면 미세누수 의심 알림
- `actual_running=false`가 반복되면 "명령은 갔는데 실제로 안 도는" 하드웨어 이상으로 별도 플래그

**(C) 주펌프 — 상시 AI 분류 (`server/nuisance_alarm_classifier.py`와 별개 모델)**
- `MAIN_SEND_INTERVAL_MS`(3초)마다 오는 `rms`/`peak`/`duty_cycle`을 RandomForest로 분류
- 클래스: 정상운전 / 체절운전 / 유량저하 / 공회전 / 기동실패

**(D) 대시보드(Flutter) 반영**
- 유량(L/min) 표시 위젯 추가
- 헤더 압력 vs 성능시험배관 압력 구분 표시
- 충압펌프 작동빈도 추이 그래프
- H-Q 곡선 그래프 (성능시험 결과)

## 7. 알려진 이슈 / 트러블슈팅 기록

- **INA219 I2C 미인식**: 브레드보드 접촉불량이 원인이었음 (직결 시 0Ω 정상 확인) → 가능하면 브레드보드 경유 없이 직결 권장
- **INA219 Bus Voltage 비정상**: ESP32 GND ↔ 파워서플라이(-) 공통 연결 누락이 원인 → 반드시 별도 선으로 직결
- **두 펌프 동시기동**: 릴레이 NO 이후 각 펌프(-) 라인이 악어클립 하나에 같이 물려있던 것이 원인 → 반드시 분리
- **I2C 주소 충돌(0x40/0x41)**: A0 패드가 없는 저가 INA219 클론 보드의 경우 `TwoWire(1)`로 I2C 버스 자체를 분리하는 대안 필요 (v7 코드는 A0 패드 있는 보드 기준)
