# 소화기 실험 가이드 — 조립부터 실험까지

> 이 문서 하나만 보고 소화기 모듈(리프노드 4개 + 게이트웨이)을 처음부터 끝까지 완성할 수 있게 정리했습니다.

---

## 0. 목표 정리

**법정 점검 항목**: 소화기 압력게이지 점검 — 근데 게이지가 500원짜리 동전보다 조금 큰 크기라 센서 부착이 물리적으로 불가능해, **"제자리에 있는가(도난·분실)"로 점검 목표를 재정의**했습니다.

**우리 시스템이 하는 일 — 2단계 판정**
1. **가속도 이벤트 감지** (즉시) — 소화기가 들어올려지는 순간 MPU6500이 감지
2. **게이트웨이 연결상태 확인** (오탐 필터) — 이벤트 후 일정 시간 동안 같은 층 게이트웨이와 통신이 유지되는지 확인. 유지되면 단순 접촉(오탐), 끊기면 이탈 확정

---

## 1. 준비물

- ESP32-C3 SuperMini × 4 (리프노드)
- ESP32 DevKitC × 1 (게이트웨이)
- MPU6500(또는 호환 MPU6050) × 4
- LiPo 배터리(PH2.0 커넥터) × 4
- TP4056 승압형 모듈(SH1.25 5V 출력) × 4
- SH1.25 to 듀폰 케이블 × 4 (또는 전선 직결)
- FSR 압력패드 × 4 (선택, 2차 보조옵션)
- 양면테이프, 소화기 실물(보유분 1개) 또는 대체 리그

---

## 2. 리프노드 조립 (4개, 동일 구성 반복)

### 배선
| 부품 | 연결 |
|---|---|
| MPU6500 SDA | ESP32-C3 GPIO8 |
| MPU6500 SCL | ESP32-C3 GPIO9 |
| MPU6500 INT | ESP32-C3 GPIO2 (또는 시뮬레이션 대체 핀) |
| LiPo → TP4056 | PH2.0 커넥터로 B+/B- 단자에 꽂기 (탈착식) |
| TP4056 SH1.25 출력(5V) | SH1.25-듀폰 케이블 → ESP32-C3 5V/GND 핀 (무납땜) |
| FSR 압력패드(선택) | ESP32-C3 ADC 핀 (예: GPIO3) |

### 조립 순서
1. ESP32-C3에 MPU6500 배선 (I2C + 인터럽트핀)
2. LiPo 배터리를 TP4056에 커넥터로 연결
3. TP4056 출력을 SH1.25 케이블로 ESP32-C3 5V/GND에 연결 — **납땜 불필요, 커넥터로만 연결**
4. ESP32-C3, MPU6500, TP4056+배터리를 양면테이프로 소화기 본체(또는 거치대)에 부착
5. **1개는 실물 소화기(보유분)에 부착**, 나머지 3개는 센서만 단독으로 리그 구성해도 무방 (여러 노드가 게이트웨이로 동시 보고되는 구조를 보여주는 용도)

### ⚠️ 캘리브레이션 필수 — 정지 상태 기준값 측정
가만히 있어도 중력 때문에 가속도 값이 0이 아닙니다. 실물마다 설치 각도가 다를 수 있으니, **부착 직후 정지 상태에서 몇 초간 값을 측정해 그걸 기준값으로 저장**하고, 그 기준값 대비 변화량으로 이벤트를 판정하세요 (하드코딩된 절대값 사용 금지).

---

## 3. 게이트웨이 조립

1. ESP32 DevKitC 1개 — 별도 센서 연결 없음, 중계 전용
2. ESP-NOW로 리프노드 4개의 신호를 수신하도록 코드 작성
3. 수신한 신호를 WiFi/UDP로 라즈베리파이 서버에 전달

---

## 4. 동작 확인

1. 리프노드 전원 켜고 시리얼 모니터로 MPU6500 값이 정상 출력되는지 확인
2. 정지 상태 기준값이 측정·저장되는지 확인 (로그로 "기준값 설정됨" 출력 확인)
3. 리프노드를 손으로 살짝 흔들어봐서 가속도 이벤트가 감지되는지 확인
4. 게이트웨이가 리프노드 신호를 받는지 확인 (ESP-NOW 페어링 상태)

---

## 5. 실험 프로토콜

### 5-1. 임계값 캘리브레이션

정지 상태에서 몇 초간 값을 관찰해 "평상시 노이즈가 최대 얼마까지 튀는지" 확인하고, 그보다 확실히 높은 값(노이즈 최댓값의 2배 정도)을 이벤트 감지 임계값으로 설정합니다. 너무 낮으면 가만히 있어도 오탐이 계속 발생합니다.

### 5-2. 오탐(단순 접촉) 시나리오

1. 리프노드를 살짝 건드리거나 청소하듯 툭 침 (가속도 이벤트 발생)
2. **게이트웨이와의 통신은 유지된 상태**로 둠 (제자리에 있으니까)
3. 일정 시간(예: 5초) 후 "오탐 처리, 무시"로 판정되는지 확인

**기록 양식**
```
시행: ___
가속도 이벤트: 발생/미발생
게이트웨이 연결: 유지/끊김
최종 판정: ___
```

### 5-3. 진짜 이탈 시나리오

1. 리프노드를 들어서 게이트웨이 통신 범위 밖으로 이동 (또는 전원을 잠깐 끊어 통신 두절 흉내)
2. 가속도 이벤트 발생 확인
3. 일정 시간 후 "이탈 확정! 경보 발생"으로 판정되는지 확인

각 시나리오 **최소 5~10회 반복**해서 판정이 일관되게 나오는지 확인하세요.

### 5-4. 배터리 소모 실측 (선택, 시간 되면)

리프노드를 완충 상태에서 하루 정도 방치하며 배터리 전압이 얼마나 떨어지는지 확인 — 이론 계산(1년 이상)과 실측이 얼마나 맞는지 참고자료로 활용 가능합니다.

---

## 6. 배터리 충전 운영 방법

평소엔 노드에 부착 상태 유지, 충전이 필요하면 **"배터리+TP4056" 세트를 통째로 분리**해서 TP4056의 USB-C 포트로 충전한 뒤 재장착합니다.
