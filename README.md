## simulation/ — 하드웨어 시뮬레이션 (Wokwi)
실물 부품 도착 전, 회로·로직을 미리 검증한 시뮬레이션입니다.

- **가스계(CO2) 모듈(로드셀)**: [Wokwi에서 열기](https://wokwi.com/projects/471159083371335681)
  - 소스: `simulation/가스계_wokwi/`
   -  **시뮬레이션 한계 (자세히)**:
    - **HX711은 공식 지원 부품이라 실물과 거의 동일하게 동작** (Wokwi 부품 중 신뢰도가 가장 높은 축).
    - **캘리브레이션 계수(CALIBRATION_FACTOR)는 임시값**: 가상 로드셀의 신호 크기가 실물과 다르기 때문에, 실물 그램 단위로 정확히 안 맞습니다. 실물 로드셀 수령 후 알고 있는 무게(동전 등)로 재보정할 예정입니다.
    - **공병중량(EMPTY_CONTAINER_WEIGHT)은 시뮬레이션에서 0으로 설정**:
      실물 상수(예: 500g)를 그대로 넣으면 시뮬레이션의 작은 임의값(수십 단위)과 스케일이 안 맞아 손실률이 이상하게 계산되는 문제를 겪었습니다.
      시뮬레이션에서는 이 값을 0으로 두고 "슬라이더 값 자체를 약제중량으로 취급"하는 방식으로 로직만 검증했습니다.
    - **검증된 것**: 약제중량 기준 손실률 계산식(총중량이 아니라 공병중량을 뺀 값 기준), 10% 임계치 도달 시 상태 전환(정상→주의→재충전 필요) 판정 로직.
    - **검증 안 된 것**: 실제 CO2 저장용기 중량대에서의 로드셀 분해능, 실물 공병중량 적용 시의 정확도.

- **소화기 모듈(자이로 + 연결끊김)**: [Wokwi에서 열기](https://wokwi.com/projects/471162307837300737)
  - 소스: `simulation/소화기_wokwi/`
  -  **시뮬레이션 한계 (자세히)**:
    - **무선통신(ESP-NOW)을 푸시버튼으로 대체**:
       실물은 리프노드가 게이트웨이와 ESP-NOW로 실제 무선 통신하면서 "연결 유지/끊김"을 판단하지만, Wokwi에서 보드 2개 간 무선통신을 구현하기 어려워
       **푸시버튼 하나로 "연결 끊김" 상태를 대신 흉내냈습니다** (버튼 안 누름=연결 유지, 누름=연결 끊김).
    - **가속도 임계값(ACCEL_THRESHOLD)을 실측으로 재조정함**:
        처음엔 하드코딩된 "정지 시 9.8"을 기준으로 잡았는데, Wokwi의 가상 MPU6050은 기본 상태에서 중력을 시뮬레이션하지 않아 항상 흔들림으로 오인식되는 문제가 있었습니다.
        **정지 상태 기준값을 setup()에서 직접 측정해서 잡는 방식**으로 바꿔 해결했습니다 — 이 방식은 실물에서도 동일하게 적용 가능합니다(설치 각도가 어떻든 자동으로 맞춰짐).
    - **검증된 것**: 가속도 이벤트 감지 → 일정 시간 대기 → 연결상태 확인 → 오탐/이탈 확정이라는 2단계 판정 흐름 전체, 정지상태 기준값 자동 캘리브레이션 로직.
    - **검증 안 된 것**: 실제 ESP-NOW 페어링·통신 성공률, 실물 배터리(LiPo+TP4056) 구동 상태에서의 동작, 여러 리프노드가 동시에 게이트웨이와 통신할 때의 처리.
 
- **수계 모듈(압력 + 전류2)**: [Wokwi에서 열기](https://wokwi.com/projects/471258535724992513)
  - 소스: `simulation/수계_wokwi/`
  -  **시뮬레이션 한계 (자세히)**:
    - **INA219 미지원**: 전류센서 2개(충압/주펌프)를 포텐셔미터로 대체(GPIO0/GPIO1). 실물은 I2C(주소 0x40/0x41)로 통신하지만, 시뮬레이션에서는 아날로그 입력값을 그대로 mA 단위처럼 취급했습니다.
    - **압력센서도 포텐셔미터로 대체**(GPIO4) — 저항분압 계산 없이 raw값을 바로 kPa로 스케일링한 단순화 버전입니다.
    - **워터펌프 자체는 시뮬레이션 대상에서 제외** — 릴레이 출력(GPIO18/19)은 신호만 내보낼 뿐 실제로 아무것도 구동하지 않습니다.
    - **duty_cycle 계산은 캡처 타이밍에 민감함**:
      한 번의 전류 샘플링(캡처)이 매우 짧은 시간(수백ms~1초) 동안 이뤄지는데, 사람이 마우스로 포텐셔미터를 그 찰나에 움직이지 않으면 "값이 안 변한 것"으로 인식되어 duty_cycle이 0으로 나올 수 있습니다.
      이는 시뮬레이션 조작 방식의 한계이며, 실물 INA219는 실제 펌프의 진짜 전류 변화를 훨씬 빠르게 읽어 이런 제약이 없습니다.
    - **검증된 것**: RMS/Peak/duty_cycle 계산 로직이 입력 변화에 정확히 비례 반응하는 것, 충압펌프 기동 엣지 감지 및 기동 간격(cycle_interval_sec) 계산 로직.
    - **검증 안 된 것**: 실제 체절/부하 상태에서의 전류 패턴, 압력값 추세로 서버가 밸브 상태를 추정하는 로직(server 쪽 별도 검증 필요), 실물 니들밸브 조작과의 연동.

    - **검증된 것**: 평상시 모니터링(3초 간격 전송) ↔ 방전시험 모드 전환, 방전시험 중 배터리 전압이 샘플마다 달라지는 것을 반영해 서버에 보내는 흐름, 시험 시간(45초) 경과 후 자동 종료 및 평상시 모드 복귀.
