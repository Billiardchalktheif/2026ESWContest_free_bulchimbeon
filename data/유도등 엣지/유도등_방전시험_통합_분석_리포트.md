# 유도등 배터리 방전시험 최종 데이터 분석 리포트
## 충전시간별(1h/2h/4h/6h/8h) 방전 반응 비교, 총 5개 데이터셋

---

## 1. 실험 개요

- **목적**: 유도등 예비전원(Ni-Cd 단일셀, 1.2V) 완충 정도에 따라 정전 시 배터리 단독 유지시간이 어떻게 변하는지 검증하고, 법정기준(20분) 충족에 필요한 최소 충전시간과 서버 판정 임계전압을 확정
- **측정 항목**: 배터리 전압(V, ESP32 ADC 1초 간격 로깅), 경과시간(초), 육안 밝기 관찰(1차 저하/2차 기능저하 시점)
- **표본**: 실험 시간 단축을 위해 **유도등 4대(개별 개체)를 각각 1h·2h·4h·6h·8h 중 하나의 충전시간에 배정**해 병렬로 진행 (동일 개체 반복충전이 아님) — 결과적으로 임계전압·판정로직이 **개체간 재현성까지 확보된 데이터**임
- ⚠️ 2h·4h 구간은 시험 도중 전원을 재투입한 이력이 있어 원본 로그에 세션이 여러 개 섞여 있음(2h=2세션, 4h=3세션). raw CSV에는 `session` 컬럼으로 구분해 그대로 보존했으며, 아래 요약은 완충 상태에서 시작한 **최초 세션(session 1)** 기준으로만 계산함.

### 2-1. 4h 구간 — 세션 분절 이슈 (신규 확인 필요)

4h 실험은 관찰 중 육안으로 "안 깜빡이나" 싶어 전원을 한 번 뽑았다가 곧바로 깜빡임을 확인하고 급히 재투입하면서, 원본 로그의 경과시간 카운터가 총 3회 리셋됨(session 1: 0~70초, session 2·3: 재투입 이후). 자동 파싱 결과 session1은 70초 만에 끊겨 300/200/100mV 진입 시점을 뽑을 수 없었고, 가장 긴 session(3번째)은 **이미 방전된 상태(약 80mV)에서 재시작**되어 다른 회차와 비교 불가능함.

**실측 관찰(수기 기록) 기준으로는** 육안 밝기 저하가 415초 근처, 200mV대(기능저하) 진입이 약 1500초(25분) 근처로 확인되어 6h·8h와 같은 추세선 상에 위치하는 것으로 보이나, 자동 계산값으로 표 2에 넣기엔 세션 경계가 불명확해 **재시험 권장** (아래 6절 참고).

## 3. 충전시간별 통합 비교 (4h 제외, 신뢰 가능한 4개 회차 기준)

| 구분 | 300mV대 진입 | 200mV대(기능저하) 진입 | 100mV대 진입 | 20분 시점 전압 | 법정기준(20분) |
|---|---|---|---|---|---|
| **1h** | 145초 (2.4분) | 167초 (2.8분) | 199초 (3.3분) | — | ❌ 미충족 |
| **2h** | 425초 (7.1분) | 477초 (8.0분) | 557초 (9.3분) | — | ❌ 미충족(근소) |
| **6h** | 503초 (8.4분) | 1511초 (25.2분) | 2231초 (37.2분) | 264.9mV | ✅ 충족 |
| **8h** | 1446초 (24.1분) | 2107초 (35.1분) | 3015초 (50.2분) | 312.1mV | ✅ 충족(여유) |

(참고용 4h 수기 관찰치: 300mV대 진입 조기, 200mV대 진입 약 1500초/25분 — 표에는 자동계산 신뢰도 문제로 별도 표기)

### 핵심 발견

1. **충전시간과 유지시간 사이 뚜렷한 비선형(가속) 관계**
   - 200mV대(기능저하) 진입 시점 기준: 1h(2.8분) → 2h(8.0분) → 6h(25.2분) → 8h(35.1분)
   - 1h→2h 구간은 완만한 증가지만, 2h→6h 구간에서 큰 폭으로 도약(8.0분→25.2분). Ni-Cd 셀이 완충에 가까워질수록 비선형적으로 유지시간이 급격히 개선되는 충전 곡선 특성으로 추정됨.
   - **법정기준(20분) 충족 최소 충전시간은 4h~6h 사이로 추정**되나, 4h 데이터의 세션 이슈로 정확한 경계는 미확정 (6절 재시험 필요).

2. **"깜빡임 시작(≈75mV)" 전압이 서로 다른 개체·충전시간과 무관하게 재현됨**
   - 1h(75.0mV), 2h(78.2mV), 4h 수기관찰(약 70~75mV) — **서로 다른 유도등 3대**에서 모두 70~78mV 범위로 일치
   - → 충전량뿐 아니라 개체차와도 무관한, 이 유도등 모델 승압회로의 **물리적 최소 동작전압**으로 판단됨(개체간 재현성 확인). 다만 이 지점은 이미 "사실상 무의미"해진 뒤라 사전예측 판정 기준으로는 부적합(아래 4절 참고).

3. **300mV 기준이 "사전예측"이라는 시스템 목적에 더 부합함 (200mV는 이미 늦은 지점)**
   - 재검토 결과: 200mV대는 육안 관찰상 "많이 어두워짐, 유도등 기능이 떨어지는 수준"으로 이미 기능저하가 진행된 시점임 — 이걸 정상/경보 경계로 쓰면 "기능이 떨어진 상태까지도 정상"이라는 논리적 모순이 생김
   - 300mV대는 "어둡지만 케이스를 덮어도 인식 가능한" 수준으로, 아직 정상 기능 범위로 볼 수 있는 마지막 지점
   - 6h·8h의 20분(1200초) 시점 전압(264.9mV, 312.1mV)을 300mV 기준으로 다시 보면: **8h는 충족(312.1mV), 6h는 근소 미달(264.9mV)** — 즉 법정기준 20분 동안 "완전한 정상 밝기"를 안정적으로 보장하려면 **8시간 이상 충전이 필요**하다는 게 더 엄밀한 결론
   - 200mV는 폐기하지 않고 **2차(이미 늦은) 경보용 보조 임계값**으로 격하하여 유지

## 4. 판정 로직 제안 (서버 담당자 검토용)

```
EVAC_DISCHARGE_THRESHOLD_V = 0.30V (300mV)   ← 주 판정 기준 (정상/경보 경계)

if 배터리전압 >= 0.30V:        → 정상 (아직 기능 유지, 케이스 덮어도 인식되는 수준)
elif 배터리전압 >= 0.20V:      → 주의 (기능저하 진행 중 — 이미 육안으로도 많이 어두움)
else (< 0.20V):                → 경보 (거의 불빛 없음 수준, 즉시 조치 필요)
```

- **주 임계값을 0.30V로 확정.** 200mV는 육안 관찰상 이미 "유도등 기능이 떨어지는 수준"으로 확인되어, 정상/경보 경계로 쓰기엔 이미 늦은 지점 — 사전예측 시스템은 기능저하가 시작되기 전(300mV대 이탈 시점)에 미리 알려야 실질적 조치 시간을 확보할 수 있음
- 200mV는 "이미 늦었지만 아직 완전 상실은 아닌" 2차 경보 보조 임계값으로 유지
- "깜빡임 시작(≈75mV)" 지점은 판정 기준으로 채택하지 않음 — 이미 기능 상실에 근접한 시점이라 조기경보 가치가 낮음
- **0.30V 기준으로 법정기준(20분) 충족 여부 재판정**: 20분 시점 전압이 6h(264.9mV)는 미달, 8h(312.1mV)는 충족 — **법정기준 20분 동안 안정적 정상작동을 보장하려면 8시간 이상 충전 필요**

## 5. 서버 담당자 전달 시 참고 사항

1. **파일**: `evac_discharge_{1h|2h|4h|6h|8h}_charged.csv` (원본 시계열), `evac_discharge_summary.csv` (회차별 요약) — 스키마 동일(`session`, `elapsed_sec`, `battery_voltage_v`, `note`)
2. **적용 위치**: `server/judge/regression.py`의 `EVAC_DISCHARGE_THRESHOLD_V`를 **0.30V**로 갱신 (기존 0.20V 검토 결과, 육안상 이미 기능저하 시점이라 사전예측 목적에 안 맞아 상향 조정됨)
3. **이상치/재검증 필요 회차**: 4h 전체(세션 분절로 자동계산 신뢰 불가, 6절 재시험 권장). 그 외 1h/2h/6h/8h 4대는 서로 다른 개체로 진행되어 **개체간 재현성이 이미 확보됨** — 추가 교차검증 불필요
4. **핵심 피처(최종)**:
   - 배터리 전압 절대값 — 200mV 임계값 비교용 (`estimated_discharge_min` 계산 근거)
   - 완충 후 경과 충전시간 — 장기 회귀(`predicted_days_to_replace`)의 별도 축, 이번 실험(방전시험)과는 다른 질문임에 유의
   - "20분 시점 전압"이 향후 회귀분석의 검증 기준점으로 활용 가능 (6h: 264.9mV, 8h: 312.1mV)
5. **다음 단계**: 4h 재시험(세션 끊김 없이 1회 연속 진행) 및 3h·5h 등 중간 지점 추가 시 회귀선 정밀도 향상 가능. 나머지 3대(유도등 2~4호기) 완충 후 200mV 임계값 재현성 교차검증 필요.

## 6. 다음에 해야 할 것

1. **4h 재시험** (여유 있으면): 이번엔 전원 재투입 없이 한 번에 연속 진행 — session 분절 없는 깨끗한 데이터 확보. 필수는 아님(1h/2h/6h/8h 4개 개체로 이미 판정로직 확정·재현성 확보됨)
2. **`EVAC_DISCHARGE_THRESHOLD_V = 0.30V` 서버 반영**: 코드/DB 업데이트 후 재배포 (0.20V는 폐기, 필요시 2차 경보 보조값으로만 활용)
3. **4대 유도등을 하나의 ESP32(GPIO32/33/34/35)에 동시 배선, `evac_light_node_v2.ino` 정식 배포판 전환**: WiFi 자격증명·서버IP 채워서 실연동 확인
4. **회귀분석(장기 추세)과의 연계**: 이번 방전시험 데이터는 "1회성 성능검사"이며, 장기 열화 추세는 `ml/evaluate_predictions.py`의 합성 데이터가 별도로 담당 — 추가 실측 불필요
