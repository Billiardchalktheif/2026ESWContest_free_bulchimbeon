# 가스계(CO2) 노드 — 캘리브레이션 최종 정리

**작성일**: 2026-08-21 (최종 갱신: 2026-08-23 — 공병중량 실측치·임계값 확정 반영)
**대상 파일**: `gas_node.ino`
**테스트 기간**: 2026-08-17 16:30 (SET_TIME) ~ 2026-08-21 (약 3.85일)
**테스트 방식**: 실제 CO2 용기 대신 자동 방향제 분사기(7분 30초 간격 분사)를 무게손실 시뮬레이션용 대체물로 사용

## 1. 하드웨어 이슈 및 해결

- 로드셀(10kg 바형 2개 병렬) 신호선(흰/초록) 접촉불량 발견 — 손으로 흔들 때 raw 값이 -1.5M~-3.2M까지 튀는 것으로 진단(정상 범위 ±650K 근처). 실시간 진단용 `MONITOR`/`STOP` 시리얼 명령으로 배선 4가닥을 개별로 흔들어보며 원인 특정.
- 원인: E+/E- (전원)보다 A+/A- (신호선)이 HX711 내부에서 ~128배 증폭되기 때문에 접촉저항 영향이 훨씬 크게 증폭됨.
- 조치: 신호선 납땜 처리 → 흔들림 테스트 시 편차가 ±162g 수준에서 ±16g 수준으로 개선 확인.
- **캘리브레이션 계수 변경 이력**: `420.0`(임시값) → `93.07`(502g 실측 역산) → **`87.9`**(납땜 후 재캘리브레이션, 501g 실측 기준). *하드웨어를 물리적으로 만질 때마다(납땜 등) raw 신호 특성이 바뀌므로 재캘리브레이션이 필요했음.*

## 2. 온도 드리프트 발견 (중요 — 소프트웨어팀 공유 필요)

- 테스트 도중 에어컨을 껐다 켰다 하면서 로드셀 판독값이 최대 ±50g 수준으로 요동치는 현상 발견.
- 실측(전자저울) 대조로 확인:
  - 테스트 시작 시점 실측: **501g**
  - 테스트 종료 시점 실측: **458g**
  - 같은 시점 시스템 판독값(에어컨 off 누적 상태): **~407g** → 시스템이 실제보다 약 50g 낮게 표시하는 절대오차 확인
- 원인: 로드셀(스트레인게이지)과 HX711 모두 온도 의존적 드리프트가 있음 — 저가 바형 로드셀은 온도보상이 부실해 영향이 큼.
- **중요**: 이 오차는 배율(calibration factor) 오차가 아니라 **영점(TARE) 오차**라서 %손실 계산에서 상쇄되지 않음. 절대 중량값의 신뢰도에 직접 영향을 줌.
- 완화책: 에어컨을 상시 가동해 온도를 안정시킨 구간만 분리해서 분석에 사용(§3).
- **향후 과제**: 서미스터 보유 중이나 이번 일정상 온도보상 로직은 미구현. 온도센서 기반 보정(raw 보정, `initial` 기준선은 건드리지 않는 방식) 또는 주기적 실측 대조+오프셋 보정 절차 도입이 필요. 실제 CO2 저장실은 법적으로 40도 이하 유지 의무가 있어 이번 책상 테스트보다는 온도 변동폭이 작을 것으로 예상되나, 근본 해결은 아님.
  - 서미스터는 **배선만으로는 보정이 되지 않음** — (1) ADC 핀에 분압회로로 연결해 온도값을 읽는 배선/펌웨어, (2) 무게를 고정한 채 온도만 변화시켜(에어컨 on/off 반복 등) raw값 드리프트를 온도의 함수로 특성화하는 짧은(수 시간 단위) 실측, (3) 그 결과로 얻은 offset(온도) 보정식을 raw→중량 변환 단계에 적용, (4) 고정 중량으로 재검증까지 4단계가 필요. 다만 이번 3일 테스트처럼 다시 여러 날을 돌릴 필요는 없고, 반나절~하루 정도의 온도 스윕 실측이면 충분함.

## 3. 회귀분석 검증 결과

- 전체 로그(817개 유효 포인트, 5분 간격) 중 에어컨을 상시 가동해 온도가 안정적이었던 구간(2026-08-20 14:00 ~ 종료, 약 22.8시간)만 추려서 검증.
- 이 구간의 **앞 70%**만으로 1차 선형회귀를 학습시켜 "10% 손실 임계값(450.9g, 시작 실측 501g 기준) 도달 시점"을 예측하고, 나머지 구간에서 실제 도달 시점과 대조:

| 항목 | 값 |
|---|---|
| 회귀 적합도 (R², 학습 구간) | 0.951 |
| 기울기 | -4.88 g/h (-117.0 g/day) |
| 예측 도달 시점 | 청정구간 시작 +7.85h |
| 실제 도달 시점 | 청정구간 시작 +8.67h |
| **예측 오차** | **약 49분** |

→ 짧은 구간의 데이터만으로도 향후 임계값 도달 시점을 신뢰할 만한 정확도로 예측 가능함을 실측으로 확인 (예측 방법론 자체의 유효성 검증).

> **주의**: 위 표의 "10% 임계값(450.9g)"은 **총중량 기준**으로 계산한 값이다. 아래 3-1에서 확정된 **약제중량(총중량 − 공병중량) 기준**으로 다시 계산하면 임계값 도달 시점이 훨씬 앞당겨진다. 예측 방법론(짧은 구간 회귀로 크로싱 시점 예측 가능)의 유효성은 그대로 유효하지만, 위 표의 구체적 시각(청정구간 +7.85h/+8.67h)은 총중량 기준 참고용 수치로만 사용할 것.

### 3-1. 공병중량 실측 반영 — 약제중량 기준 재계산 (2026-08-23 추가)

- 실측: 방향제(약제 역할) 장착 상태 **457g**, 방향제 제거(공병중량) **260g** → **공병중량 260g**로 확정.
- 이 값을 실측 anchor(시작 501g / 종료 457g)에 적용해 **약제중량 기준**으로 재계산:

| 항목 | 총중량 기준(기존, 참고용) | **약제중량 기준(확정)** |
|---|---|---|
| 시작 (약제중량 = 총중량 − 260g) | 501g | 241g |
| 종료 | 457~458g | 197g |
| 3.85일간 손실률 | 8.58% | **17.8~18.3%** |
| 환산 손실 속도 | 2.23%/day | **약 4.7%/day** |
| 시작 시점부터 10% 도달까지 | 4.48일 | **약 2.1일 (≈51시간)** |

→ **핵심 발견**: 약제중량 기준(정확한 판정 방식)으로 보면 이번 테스트는 3.85일이 지나기 **훨씬 전인 2026-08-19 19~20시경(테스트 시작 후 약 2.1일)에 이미 10% 임계값을 초과**했다. 총중량 기준 계산은 분모(총중량)에 공병의 고정 무게(260g)가 섞여 들어가 손실률을 실제보다 절반 이하로 낮게 보여주는 착시였다 — 프로젝트 문서(`regression.py`)가 원래 요구하던 "약제중량 기준 계산"이 왜 필수인지를 이번 실측이 그대로 증명한 셈.
- 이 260g은 **이번 테스트 리그(방향제 분사기 + 기동용기)에 한정된 실측치**다. 실제 CO2 소화설비 배치 시에는 해당 용기의 진짜 공병중량을 반드시 별도 실측해 `EMPTY_CONTAINER_WEIGHT_G`에 반영해야 한다(현장마다 용기 규격이 다를 수 있음).
- §3 상단 회귀분석(R²=0.951, 예측오차 49분)은 "짧은 구간 데이터로 크로싱 시점을 정확히 예측할 수 있다"는 **방법론 검증**으로는 여전히 유효하나, 그 방법론을 약제중량 기준 임계값(약 217g, 총중량 환산 시 약 477g)에 그대로 재적용한 재검증은 미수행 — 시간이 허락하면 추가로 돌릴 수 있으나 현재 우선순위상 필수는 아님(§3-1의 2-포인트 실측 기반 계산으로 헤드라인 수치는 이미 확정 가능).

## 4. 소프트웨어팀 전달 사항 — `gas_node.ino` 확정 설정값

```cpp
const int   HX711_DOUT_PIN = 16;
const int   HX711_SCK_PIN  = 17;
const float DEFAULT_CALIBRATION_FACTOR = 87.9;   // 납땜 후 재캘리브레이션 확정값
const byte  AVG_SAMPLES = 30;                    // 노이즈 저감용 평균 샘플 수
```

- `initialWeightG`은 ESP32 Preferences(NVS)에 저장되며, **설치 시 반드시 `TARE` → `SET_INITIAL` 순서로 현장에서 재설정 필요** (이 문서의 87.9는 로드셀 계수일 뿐, 기준중량은 설치 환경마다 다시 잡아야 함).
- 서버(`bulchimbeon_sw/server/config.py`) 반영 확정 사항 (2026-08-23 확정, 예선 시연 기준):

  ```python
  DEFAULT_GAS_TYPE = "co2"
  GAS_LOSS_THRESHOLD_PCT = {
      "co2": 10.0,    # 매뉴얼 1권 기준 확정
      "halon": 5.0,   # 압력손실 10% 또는 중량손실 5% 중 중량 기준 채택 (매뉴얼 확정)
      "inert": 5.0,   # IG계열 압력손실 5% 기준을 중량센서로 근사 적용 (기존 유지)
  }
  DEFAULT_EMPTY_CONTAINER_WEIGHT_G = 260.0  # 예선 시연용(방향제 분사기 리그) 실측값
  ```

  1. **공병중량 반영 (해결)**: 손실률은 총중량이 아니라 "총중량 − 공병중량"(약제중량) 기준으로 계산 확정. **예선 시연까지는 방향제 분사기 리그를 그대로 사용하므로, 그 리그 실측값인 `260.0`을 그대로 확정값으로 사용.** 로직 자체는 이미 `regression.py`의 `_agent_loss_pct()`에 구현되어 있어 코드 수정은 불필요, `config.py`의 상수값만 반영하면 됨.
     - ⚠️ **단, 결선에서 실제 CO2 용기로 교체한다면 그 시점에 반드시 재실측해서 이 값을 교체할 것** — 260g은 방향제 분사기+기동용기 조합 전용 실측치이지, 실제 CO2 소화설비 용기의 공병중량이 아님.
  2. **임계값 확정 (해결)**: 소방시설 점검관리 매뉴얼 1권 기준 **CO2 중량손실 10%**, 할론은 **중량손실 5%**로 확정. (코드 주석의 "미확정/보수적으로 5%" 문구 제거.)
  3. 위 두 항목이 확정되면서 §3-1의 재계산 결과, 이번 테스트는 총중량 기준 헤드라인(8.58%/4.48일)보다 훨씬 이른 시점(테스트 시작 후 약 2.1일)에 이미 10% 임계값을 초과한 것으로 확인됨 — 판정 로직이 약제중량 기준으로 정확히 동작하는지 서버단에서 다시 한번 확인 권장.
